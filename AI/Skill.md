# AI Skill
**AI의 Skill(스킬)은 AI가 특정 업무를 일정한 방식과 품질로 수행하도록 만든 ‘재사용 가능한 업무 매뉴얼 묶음’이다.** 작업 지침뿐 아니라 참고 자료, 템플릿, 실행 스크립트도 포함할 수 있다.

## 핵심 개념

| 궁금한 점             | 핵심 답변                       |
| ----------------- | --------------------------- |
| 무엇인가?             | AI에게 특정 업무의 처리 방법을 알려주는 패키지 |
| 왜 사용하는가?          | 반복 설명을 줄이고 작업 기준을 유지하기 위해   |
| 무엇이 들어가는가?        | 지침, 참고 자료, 템플릿, 선택적 코드      |
| 언제 적용되는가?         | 사용자가 지정하거나 AI가 관련 스킬을 선택할 때 |
| 모델을 다시 학습시키는가?    | 모델을 재학습하지 않고 작업 중 지침을 읽어 적용 |
| 설치하면 모든 작업이 가능한가? | 필요한 도구, 데이터, 접근 권한도 있어야 함   |

## Skill은 AI에게 주는 업무 매뉴얼

새로운 직원에게 “주간 보고서를 작성해 주세요”라고 하면, 어떤 자료를 보고 어떤 형식으로 작성할지 스스로 판단해야 한다.

다음과 같은 매뉴얼을 제공하면 기준이 분명해진다.

> 1. 이번 주 실적과 지난주 실적을 비교한다.
> 2. 변화가 큰 항목 세 가지를 먼저 설명한다.
> 3. 확인되지 않은 원인은 추정으로 표시한다.
> 4. 마지막에 다음 주 할 일을 정리한다.

**이 절차와 보고서 양식을 묶어 AI가 필요할 때 꺼내 쓰게 만든 것이 스킬**이다.

매번 긴 설명을 반복할 필요가 줄고, 결과물의 형식과 검토 기준도 유지하기 쉬워진다. 다만 같은 스킬을 사용하더라도 결과가 매번 완전히 같지는 않는다.

## 프롬프트·도구·MCP·플러그인과의 차이

### 각 기능이 맡는 역할

|개념|주요 역할|보고서 작성 예시|
|---|---|---|
|**프롬프트**|이번에 할 일을 요청|“8월 매출 보고서를 작성해줘”|
|**Skill**|업무 절차와 품질 기준 제공|기간 확인 → 계산 → 분석 → 검증|
|**도구·Tool**|개별 동작 실행|파일 읽기, 계산, 차트 생성|
|**MCP**|외부 도구와 데이터를 연결하는 표준|매출 시스템의 조회 기능 연결|
|**플러그인·Plugin**|확장 기능을 설치·배포하는 패키지|스킬과 외부 연결을 함께 제공|
|**에이전트·Agent**|요청을 해석하고 작업 수행|매뉴얼과 도구를 활용하는 담당자|

### 함께 작동하는 예시

매출 보고서를 작성한다면 다음처럼 역할이 나뉠 수 있다.

- **사용자 요청:** “이번 달 매출을 분석해줘.”
- **스킬:** 비교 기간, 분석 순서, 보고서 형식을 안내합니다.
- **MCP로 연결된 도구:** 매출 데이터를 조회합니다.
- **계산·문서 도구:** 수치를 계산하고 보고서를 만듭니다.
- **에이전트:** 전체 작업을 진행하고 결과를 확인합니다.

외부 연결이 필요 없는 글쓰기 스킬은 지침과 참고 자료만으로도 사용할 수 있다.

## 스킬의 내부 구성

### 핵심 파일: `SKILL.md`

스킬의 중심에는 `SKILL.md`라는 텍스트 문서가 있다. `.md`는 제목과 목록 등을 표현하는 Markdown 파일 형식이다.

```
my-skill/
├── SKILL.md       ← 이름, 설명, 작업 지침
├── references/    ← 참고 문서
├── scripts/       ← 반복 작업을 수행하는 코드
└── assets/        ← 템플릿, 이미지 등
```

`SKILL.md`가 필수이며, 나머지는 필요에 따라 추가한다. **지침만으로도 스킬을 만들 수 있으므로 코딩이 반드시 필요한 것은 아니다.**

### 예시

아래는 예시이다.

```
---
name: meeting-summary
description: 회의 메모를 결정 사항과 후속 작업 중심으로 정리할 때 사용한다.
---

회의 내용을 다음 기준으로 정리한다.

1. 회의 목적을 한 문장으로 작성한다.
2. 주요 논의와 확정된 결정을 구분한다.
3. 후속 작업은 담당자와 기한을 함께 표시한다.
4. 담당자나 기한이 없으면 "미정"으로 표시한다.
5. 원문에 없는 합의나 결정을 만들어내지 않는다.

출력 순서:
- 회의 목적
- 주요 논의
- 결정 사항
- 후속 작업 표
```

좋은 지침은 “잘 정리해라”에서 끝나지 않는다. **무엇을 구분하고, 정보가 빠졌을 때 어떻게 처리할지**까지 설명한다.

## AI가 스킬을 사용하는 과정

### 필요한 지침을 선택해 읽는 방식

**사용자 요청 → 관련 스킬 선택 → 지침 읽기 → 자료·도구 활용 → 결과 작성**

AI는 처음부터 모든 스킬의 전체 내용을 읽지 않는다. 이름과 설명을 먼저 확인하고, 사용할 스킬의 상세 지침을 읽는다. 이를 **점진적 로딩·Progressive Disclosure**이라고 한다.

### 직접 지정과 자동 선택

| 방식        | 요청 예시                        | 특징                    |
| --------- | ---------------------------- | --------------------- |
| **직접 지정** | “`meeting-summary` 스킬로 정리해줘” | 원하는 처리 방식을 명시         |
| **자동 선택** | “이 회의에서 결정 사항과 할 일을 정리해줘”    | 요청과 스킬 설명이 맞으면 AI가 선택 |

따라서 스킬 설명에는 **어떤 요청에서 사용해야 하는지**를 분명하게 적는 것이 중요하다.

## 실제로 활용할 수 있는 업무

|업무|스킬에 담을 기준|기대 효과|
|---|---|---|
|**보고서 작성**|구성 순서, 지표 정의, 출처 표기|분석 기준과 형식 유지|
|**회의록 정리**|논의·결정 구분, 담당자·기한 추출|후속 작업 누락 감소|
|**디자인**|색상, 서체, 간격, 브랜드 규칙|시각적 일관성|
|**코딩**|구현 규칙, 오류 처리, 검증 절차|프로젝트 기준 준수|
|**데이터 분석**|결측값 처리, 집계 단위, 검산|계산 과정의 일관성|
|**고객 응대**|말투, 답변 구조, 담당자 연결 조건|응대 기준 유지|
|**교육 자료 제작**|난이도, 설명 순서, 문제 형식|학습 대상에 맞는 구성|

예를 들어 디자인 스킬에 “고급스럽게 만들어라”만 적으면 해석 범위가 넓다. **본문 크기, 여백, 색상, 버튼 상태, 모바일 확인 항목**을 정의하면 결과를 구체적으로 평가할 수 있다.

## 기억·검색·학습·자동화와의 차이

### 스킬은 업무 처리 방법을 담는다

|구분|핵심 질문|예시|
|---|---|---|
|**기억·개인화**|사용자는 무엇을 선호하는가?|한국어 설명을 선호함|
|**참고 자료·검색**|어떤 정보가 필요한가?|제품 설명서에서 사양 확인|
|**Skill**|이 업무를 어떻게 처리하는가?|사양 비교 후 차이와 선택 기준 정리|
|**파인튜닝**|학습으로 모델의 행동을 어떻게 바꾸는가?|예제를 통해 모델 가중치 조정|
|**예약·자동화**|언제 또는 어떤 조건에서 실행하는가?|매주 월요일 보고서 작성 실행|

### 스킬을 사용해도 모델이 영구 학습하는 것은 아니다

스킬은 **저장된 지침을 작업할 때 읽어 적용하는 방식**이다. 사용했다는 이유만으로 모델 내부에 영구적으로 학습되는 것은 아니다.

또한 보고서 스킬을 만들어도 매주 자동 실행되지는 않는다. 정기 실행에는 별도의 예약·자동화 설정이 필요하다.

## 좋은 스킬을 만드는 기준

### 설계할 때 정해야 할 일곱 가지

|항목|작성할 내용|
|---|---|
|**목적**|어떤 업무를 해결하는가?|
|**적용 조건**|언제 사용하고, 언제 사용하지 않는가?|
|**입력**|어떤 자료가 필요한가?|
|**절차**|어떤 순서로 작업하는가?|
|**예외 처리**|자료가 없거나 모순되면 어떻게 하는가?|
|**결과물**|어떤 형식으로 내보내는가?|
|**검증**|무엇을 확인하면 완료로 볼 수 있는가?|

### 추상적 표현을 확인 가능한 기준으로 바꾸기

|추상적인 지침|구체적인 지침|
|---|---|
|정확하게 작성한다|항목별 합계와 전체 합계가 일치하는지 확인한다|
|보기 좋게 정리한다|핵심 결론을 먼저 쓰고 비교 항목은 표로 정리한다|
|빠진 정보를 처리한다|담당자와 기한이 없으면 “미정”으로 표시한다|
|충분히 검토한다|출처, 계산, 누락 항목을 각각 확인한다|

스킬을 테스트할 때는 정상적인 요청 외에도 **자료가 부족한 경우, 적용하면 안 되는 요청, 자료가 서로 모순되는 경우**를 확인하는 것이 좋다.

## 장점과 한계

### 주요 장점

- **반복 설명 감소:** 자주 쓰는 작업 지침을 재사용한다.
- **일관성 향상:** 형식과 판단 기준을 유지하기 쉽다.
- **노하우 공유:** 개인이나 팀의 업무 방법을 전달할 수 있다.
- **개선 용이:** 지침을 수정해 이후 작업에 반영할 수 있다.

### 알아둘 한계

- **정확성을 보장하지 않는다.** 입력 오류나 판단 실수는 여전히 발생할 수 있다.
- **접근 권한을 만들지 않는다.** 외부 서비스에는 연결과 권한이 필요하다.
- **개수와 성능이 비례하지 않는다.** 중복되거나 충돌하는 지침은 혼란을 줄 수 있다.
- **유지보수가 필요하다.** 업무 규칙과 도구가 바뀌면 스킬도 수정해야 한다.

## 시작하는 방법

### 반복해서 설명하던 업무 하나를 고르세요

처음에는 **“내 형식으로 회의록 정리하기”**처럼 범위가 작고 결과를 비교하기 쉬운 업무가 적합하다.

1. 자주 반복하는 업무를 하나 선택한다.
2. 원하는 결과물의 예시를 준비한다.
3. 작업 순서와 반드시 지킬 기준을 적는다.
4. 스킬로 만든 뒤 실제 자료에 적용한다.
5. 부족한 부분을 구체적인 지침으로 보완한다.
