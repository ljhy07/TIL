임베딩(embedding)은 **텍스트·이미지·사용자·상품처럼 복잡한 대상을, 의미가 보존된 숫자 벡터로 변환하는 기술**이다.

예를 들어 문장을 임베딩하면 다음처럼 수백~수천 개 숫자로 표현된다.

```
"고양이가 소파에서 잔다"
→ [0.12, -0.48, 0.91, ..., 0.07]
```

이 숫자 하나하나를 사람이 직접 해석하기는 어렵지만, 전체 벡터의 위치와 방향에는 문장의 의미가 반영된다. 의미가 비슷한 대상은 벡터 공간에서도 가까운 위치에 놓는다.

---

## 직관


```
A: 강아지가 공원에서 뛰고 있다
B: 개가 야외에서 달리고 있다
C: 주식 시장의 금리가 상승했다
```

임베딩 공간에서는 대략 다음 관계가 만들어진다.

```
거리(A, B) = 가까움
거리(A, C) = 멂
```

A와 B는 단어가 정확히 일치하지 않아도 의미가 비슷하다. 임베딩은 이런 **의미적 유사성**을 숫자 사이의 거리로 계산할 수 있게 한다.

전통적인 키워드 검색은 `"강아지"`와 `"개"`를 서로 다른 문자열로 볼 수 있지만, 임베딩 검색은 두 단어가 의미상 가깝다는 사실을 활용할 수 있다.

---

## 벡터

벡터는 숫자의 배열이다.

```
[0.2, -0.7, 0.4]
```

이것을 3차원 공간의 좌표라고 생각할 수 있습니다. 실제 임베딩은 보통 훨씬 많은 차원을 사용한다.

```
3차원 벡터:     [0.2, -0.7, 0.4]
1536차원 벡터: [0.2, -0.7, 0.4, ..., 0.1]
```

차원이 많아질수록 모델은 대상의 다양한 특징을 표현할 수 있다. 텍스트 임베딩에서는 다음과 같은 성질들이 여러 차원에 분산되어 표현될 수 있다.

- 주제
- 대상
- 감정
- 문맥
- 문체
- 의도
- 전문 분야
- 문장 간 관계

다만 “37번째 숫자는 감정”처럼 각 차원에 명확한 이름이 붙는 것은 아니다. 의미는 여러 차원에 걸쳐 **분산 표현**된다.

---

## 임베딩 제작

임베딩 모델은 많은 데이터를 학습하면서 어떤 대상들이 서로 관련되어 있는지 배운다.

텍스트 모델의 학습 목표는 모델에 따라 다르지만, 개념적으로는 다음과 같다.

- 비슷한 의미의 문장을 가까이 배치한다.
- 관련 없는 문장을 멀리 배치한다.
- 문맥에서 비슷한 역할을 하는 표현을 유사하게 표현한다.

예를 들어 학습 데이터에 다음과 같은 관계가 반복해서 나타나면:

```
"자동차를 수리하다"
"차량을 정비하다"
```

모델은 `자동차`와 `차량`, `수리`와 `정비`가 비슷한 문맥에서 사용된다는 사실을 학습한다.

현대의 임베딩 모델은 대개 Transformer 계열 신경망을 사용한다. 입력 텍스트를 토큰으로 분리하고, 각 토큰의 문맥적 표현을 계산한 뒤 이를 하나의 고정 길이 벡터로 압축한다.

```
문장
  ↓ 토큰화
토큰 목록
  ↓ Transformer
문맥적 토큰 표현
  ↓ pooling 또는 전용 출력
문장 임베딩
```

## 단어 임베딩과 문맥 임베딩

### 고전적인 단어 임베딩

Word2Vec, GloVe 같은 초기 방식은 각 단어에 거의 고정된 벡터를 부여한다.

```
"은행" → 항상 같은 벡터
```

그러나 한국어의 `은행`에는 최소 두 가지 의미가 있다.

```
은행에서 돈을 인출했다
길에서 은행 열매를 밟았다
```

고정된 단어 임베딩만으로는 이런 다의어를 다루기 어렵다.

### 문맥 임베딩

현대 모델은 주변 문장을 함께 고려한다.

```
"은행에서 돈을 인출했다"의 은행
→ 금융기관에 가까운 표현

"은행 열매를 밟았다"의 은행
→ 식물에 가까운 표현
```

따라서 같은 단어라도 문맥에 따라 다른 내부 표현을 갖는다.

### 문장·문서 임베딩

검색이나 추천에서는 단어 하나가 아니라 문장, 문단, 문서 전체를 하나의 벡터로 만드는 경우가 많다.

```
"환불은 구매 후 7일 이내 가능합니다."
→ 문장 벡터
```

사용자의 질문도 같은 방식으로 변환한다.

```
"일주일 안에 반품할 수 있나요?"
→ 질문 벡터
```

두 벡터가 가까우면 관련 문서로 판단한다.

## 유사도 계산

가장 일반적인 방법은 **코사인 유사도**이다.

벡터 \(A\)와 \(B\)가 있을 때:

\[ \text{cosine similarity}(A,B) = \frac{A \cdot B}{\|A\|\|B\|} \]

쉽게 말하면 두 벡터가 가리키는 **방향이 얼마나 비슷한지** 측정한다.

일반적인 해석은 다음과 같다.

- 1에 가까움: 매우 유사
- 0에 가까움: 관련성이 낮음
- -1에 가까움: 반대 방향

실제 임베딩 모델의 점수 분포는 모델과 데이터에 따라 다르기 때문에, `0.8 이상이면 항상 동일 의미` 같은 보편적인 기준은 없다. 검증 데이터로 적절한 임계값을 정해야 한다.

그 밖에 다음 거리 함수도 사용된다.

- 유클리드 거리
- 내적
- 맨해튼 거리

모델이 어떤 방식으로 학습되었는지에 따라 권장되는 계산법이 다르다.

## 임베딩 검색의 동작 과정

문서 검색 시스템은 보통 다음처럼 작동한다.

```
문서 수집
  ↓
작은 단위로 분할(chunking)
  ↓
각 조각을 임베딩
  ↓
벡터 데이터베이스에 저장
```

사용자가 질문하면:

```
질문 입력
  ↓
질문을 임베딩
  ↓
가장 가까운 문서 벡터 검색
  ↓
관련 문서 반환
```

예를 들어 문서가 다음과 같이 저장되어 있다고 하면

```
문서 1: 비밀번호 변경 방법
문서 2: 상품 환불 정책
문서 3: 배송 조회 방법
```

사용자가 `"산 물건을 취소하고 돈을 돌려받고 싶어요"`라고 질문하면, `환불`이라는 정확한 단어가 없어도 문서 2의 임베딩과 가까울 가능성이 높다.

---

## 벡터 데이터베이스

벡터 데이터베이스는 임베딩을 저장하고, 주어진 벡터와 가까운 벡터를 빠르게 찾는 시스템이다.

일반 데이터베이스에서는 보통 정확한 값이나 조건으로 검색한다.

```
WHERE category = 'refund'
```

벡터 검색에서는 다음과 같은 요청을 수행합니다.

```
이 질문 벡터와 가장 가까운 문서 5개를 찾아라
```

데이터가 많으면 모든 벡터를 하나씩 비교하기 어렵기 때문에 ANN(Approximate Nearest Neighbor), 즉 **근사 최근접 이웃 검색**을 사용한다. 약간의 정확도를 양보하고 검색 속도를 크게 높이는 방식이다.

대표적인 인덱스 방식에는 HNSW, IVF 등이 있다.

## 주요 활용 사례

### 의미 기반 검색

표현이 달라도 의미가 비슷한 결과를 찾는다.

```
검색어: 노트북 배터리가 너무 빨리 닳아요
문서: 휴대용 컴퓨터의 전원 지속 시간 개선 방법
```

### 추천 시스템

사용자와 상품을 같은 벡터 공간에 표현할 수 있다.

```
사용자 취향 벡터 ↔ 영화 벡터
```

가까운 영화를 추천하는 방식이다.

### 문서 분류

문서 임베딩을 사용해 문의 유형, 뉴스 카테고리, 스팸 여부 등을 분류한다.

### 군집화

비슷한 임베딩을 묶어서 데이터에 어떤 주제들이 존재하는지 발견할 수 있다.

### 중복 탐지

표현만 바꾼 유사 문서나 유사 질문을 찾는다.

### 이상 탐지

정상 데이터의 임베딩 분포에서 지나치게 멀리 떨어진 대상을 찾는다.

### 이미지·텍스트 연결

멀티모달 모델은 이미지와 문장을 같은 벡터 공간에 배치할 수 있다.

```
"고양이가 창가에 앉아 있는 사진"
↔ 실제 고양이 이미지
```

이를 이용하면 자연어로 이미지를 검색할 수 있다.

## 임베딩의 장점

- 정확한 키워드가 없어도 의미로 검색할 수 있다.
- 비정형 데이터를 수치 계산에 사용할 수 있다.
- 검색, 분류, 추천, 군집화에 같은 표현을 재사용할 수 있다.
- 대규모 데이터에서도 벡터 인덱스를 이용해 빠르게 검색할 수 있다.
- 다국어 모델은 서로 다른 언어의 비슷한 문장을 가까이 배치할 수 있다.

예를 들어 잘 학습된 다국어 모델에서는 다음 문장들이 가까울 수 있다.

```
"배송은 언제 도착하나요?"
"When will my order arrive?"
```

## 한계와 주의점

### 의미가 비슷하다고 사실까지 같은 것은 아니다

```
계약 기간은 1년이다
계약 기간은 2년이다
```

두 문장은 구조와 주제가 거의 같으므로 임베딩이 매우 가까울 수 있지만, 핵심 사실은 다르다.

### 부정 표현에 약할 수 있다

```
이 약을 복용해야 한다
이 약을 복용하면 안 된다
```

단어 대부분이 같아 유사도가 높게 나올 가능성이 있다. 법률·의료·재무처럼 정확성이 중요한 분야에서는 임베딩 점수만 믿으면 안된다.

### 긴 문서를 하나의 벡터로 만들면 정보가 희석된다

수십 페이지 문서를 하나의 벡터로 압축하면 세부 주제가 사라질 수 있다. 그래서 문서를 적당한 크기의 청크로 나눈다.

### 모델이 바뀌면 벡터를 다시 만들어야 한다

서로 다른 임베딩 모델이 만든 벡터는 일반적으로 같은 공간에 있지 않다.

```
모델 A로 만든 문서 벡터
모델 B로 만든 질문 벡터
```

이 둘의 유사도를 직접 비교해서는 안된다. 모델을 교체하면 기존 데이터도 다시 임베딩해야 하는 경우가 많다.

### 임베딩도 민감 정보를 담을 수 있다

원문을 그대로 복원하기 어렵다고 해서 완전히 익명인 것은 아니다. 접근 권한, 저장 정책, 삭제 정책을 갖춰야 한다.

## 검색 품질을 좌우하는 요소

좋은 모델 하나만 선택한다고 검색 품질이 보장되지는 않는다. 실제로는 다음 요소가 함께 중요하다.

### 청크 크기

너무 작으면 맥락이 사라지고, 너무 크면 여러 주제가 섞인다.

### 메타데이터 필터

벡터 유사도만 사용하지 않고 날짜, 언어, 조직, 문서 종류 등의 조건을 함께 적용한다.

```
의미적으로 유사함
AND 부서 = 인사팀
AND 작성일 >= 2026-01-01
```

### 하이브리드 검색

임베딩 검색과 키워드 검색을 결합한다.

- 임베딩 검색: 의미와 의도에 강함
- 키워드 검색: 상품 코드, 사람 이름, 오류 번호 같은 정확한 문자열에 강함

실무에서는 둘을 섞는 방식이 대체로 안정적이다.

### 재순위화

벡터 검색으로 후보 문서를 넓게 가져온 뒤, 더 정교한 모델이 관련성 순서를 다시 계산한다.

```
벡터 검색 Top 50
→ reranker
→ 최종 Top 5
```

### 평가 데이터

실제 사용자 질문과 정답 문서의 쌍을 만들어 다음 지표로 평가한다.

- Recall@K: 정답이 상위 K개 안에 포함되는 비율
- Precision@K: 상위 K개 중 실제 관련 결과의 비율
- MRR: 첫 번째 정답이 얼마나 높은 순위에 있는지
- nDCG: 여러 관련 결과의 순위 품질
