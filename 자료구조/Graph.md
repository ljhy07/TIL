## 그래프의 개념

**그래프(Graph)는 여러 대상과 그 대상 사이의 관계를 표현하는 자료구조이다.** 대상은 **정점(Vertex)** 또는 **노드(Node)** 로 표현하고, 관계는 **간선(Edge)** 으로 표현한다.

배열과 연결 리스트가 주로 데이터를 순서대로 관리한다면, 그래프는 데이터 사이의 복잡한 연결 관계를 관리한다. 하나의 정점이 여러 정점과 연결될 수 있으며, 연결이 순환하거나 일부 정점이 서로 떨어져 있을 수도 있다.

그래프가 사용되는 대표적인 사례는 다음과 같다.

- **지도와 길 찾기**에서는 장소를 정점으로, 도로를 간선으로 표현한다.
- **소셜 네트워크**에서는 사용자를 정점으로, 친구 관계나 팔로우 관계를 간선으로 표현한다.
- **컴퓨터 네트워크**에서는 장치를 정점으로, 통신 연결을 간선으로 표현한다.
- **과목 수강 계획**에서는 과목을 정점으로, 선수 과목 관계를 간선으로 표현한다.
- **웹 검색**에서는 웹 페이지를 정점으로, 페이지 사이의 링크를 간선으로 표현한다.

그래프의 핵심은 데이터를 저장하는 것뿐 아니라, **어떤 대상이 어떤 대상과 연결되어 있는지 분석하는 것**이다.

## 그래프의 기본 구성

### 정점과 간선

그래프는 일반적으로 다음과 같이 나타낸다.

$G = (V, E)$

- $G$는 그래프이다.
- $V$는 정점의 집합이다.
- $E$는 간선의 집합이다.

예를 들어 다음과 같은 그래프가 있다고 가정한다.

```
    A
   / \
  B   C
   \ /
    D
    |
    E
```

이 그래프의 정점과 간선은 다음과 같다.

```
정점 집합: {A, B, C, D, E}
간선 집합: {A-B, A-C, B-D, C-D, D-E}
```

정점은 5개이고 간선도 5개이다. A와 D는 직접 연결되어 있지 않지만, B나 C를 거쳐 이동할 수 있다.

이후 복잡도를 설명할 때는 정점 수를 $n = |V|$, 간선 수를 $m = |E|$으로 나타낸다.

### 인접

**두 정점 사이에 간선이 있으면 두 정점은 인접한 상태이다.**

위 그래프에서 A와 B는 인접하고, A와 C도 인접한다. A와 D는 직접 연결하는 간선이 없으므로 인접하지 않는다.

어떤 정점에 직접 연결된 정점들을 그 정점의 이웃 정점이라고 한다.

### 차수

**차수(Degree)는 정점에 연결된 간선의 수이다.**

위 그래프에서 각 정점의 차수는 다음과 같다.

|정점|차수|설명|
|---|---|---|
|A|2|B, C와 연결되어 있다.|
|B|2|A, D와 연결되어 있다.|
|C|2|A, D와 연결되어 있다.|
|D|3|B, C, E와 연결되어 있다.|
|E|1|D와 연결되어 있다.|

무방향 그래프에서는 하나의 간선이 양쪽 정점의 차수에 각각 포함된다. 따라서 모든 정점의 차수를 더하면 간선 수의 두 배가 된다.

$\sum_{v \in V} \deg(v) = 2m$

자기 자신으로 연결되는 간선이 있다면 해당 간선은 차수에 2를 기여한다.

### 경로와 경로 길이

**경로(Path)는 간선을 따라 정점들을 연결한 이동 순서이다.**

위 그래프에서 A에서 E로 가는 경로의 예시는 다음과 같다.

```
A → B → D → E
A → C → D → E
```

엄밀하게는 정점이나 간선의 반복을 허용하는 이동을 워크(Walk)로 구분하고, 정점이 반복되지 않는 경로를 단순 경로(Simple Path)라고 한다.

가중치가 없는 그래프에서 경로의 길이는 지나간 간선의 수이다. 따라서 `A → B → D → E`의 길이는 3이다.

### 사이클

**사이클(Cycle)은 출발한 정점으로 다시 돌아오는 순환 경로이다.**

위 그래프에서는 다음과 같은 사이클이 존재한다.

```
A → B → D → C → A
```

단순 사이클에서는 시작 정점과 끝 정점이 같은 것을 제외하면 정점이 반복되지 않는다.

사이클의 존재 여부는 작업 의존성 검사, 교착 상태 분석, 트리 판별 등에 활용된다.

## 그래프의 주요 종류

### 무방향 그래프

**무방향 그래프(Undirected Graph)는 간선에 방향이 없는 그래프이다.**

```
A ── B
```

A에서 B로 이동할 수 있고, B에서 A로도 이동할 수 있다. 이때 A-B와 B-A는 같은 간선을 의미한다.

친구 관계나 양방향 도로처럼 관계가 대칭적인 상황을 표현하기에 적합하다.

### 방향 그래프

**방향 그래프(Directed Graph)는 간선에 방향이 있는 그래프이다.**

```
A → B
```

A에서 B로 이동할 수 있지만, B에서 A로 이동할 수 있다는 의미는 아니다. 반대 방향으로 이동하려면 B에서 A로 향하는 간선이 별도로 있어야 한다.

팔로우 관계, 웹 페이지 링크, 일방통행 도로 등을 표현할 때 사용한다.

방향 그래프에서는 차수를 다음과 같이 나눈다.

- **진입 차수(In-degree)**는 해당 정점으로 들어오는 간선의 수이다.
- **진출 차수(Out-degree)**는 해당 정점에서 나가는 간선의 수이다.

### 가중치 그래프

**가중치 그래프(Weighted Graph)는 간선에 비용이나 수치가 부여된 그래프이다.**

```
A ──5── B
 \      /
  2    1
   \  /
    C
```

가중치는 거리, 이동 시간, 요금, 통신 비용 등을 의미할 수 있다.

위 그래프에서 A에서 B로 직접 이동하면 비용은 5이다. C를 거쳐 이동하면 비용은 $2 + 1 = 3$이다.

따라서 **간선을 가장 적게 지나는 경로와 총비용이 가장 작은 경로는 다를 수 있다.**

### 연결 그래프와 비연결 그래프

**연결 그래프(Connected Graph)는 무방향 그래프에서 모든 정점 쌍 사이에 경로가 존재하는 그래프이다.**

```
A ── B ── C
```

어떤 정점에서 출발해도 다른 모든 정점으로 이동할 수 있다.

**비연결 그래프(Disconnected Graph)는 서로 이동할 수 없는 정점들이 존재하는 그래프이다.**

```
A ── B     C ── D
```

이 그래프는 두 개의 **연결 요소(Connected Component)**로 구성되어 있다. 연결 요소는 서로 도달할 수 있는 정점들을 최대한 묶은 부분 그래프이다.

방향 그래프에서는 방향을 고려해야 하므로 연결성을 추가로 구분한다.

- **강한 연결**은 모든 정점 쌍에 대해 양방향으로 도달할 수 있는 상태이다.
- **약한 연결**은 간선의 방향을 무시했을 때 연결되는 상태이다.

### DAG

**DAG는 방향성 비순환 그래프(Directed Acyclic Graph)이다.** 방향 그래프이면서 방향을 따라 이동했을 때 사이클이 없는 그래프이다.

```
기초 문법 → 자료구조 → 알고리즘
```

작업 순서, 빌드 의존성, 선수 과목 관계 등을 표현할 때 사용한다.

DAG에서는 의존성을 지키는 처리 순서를 구하는 **위상 정렬**을 수행할 수 있다.

### 단순 그래프와 다중 그래프

**단순 그래프(Simple Graph)는 자기 자신으로 연결되는 간선과 같은 정점 쌍 사이의 중복 간선이 없는 그래프이다.**

**다중 그래프(Multigraph)는 같은 정점 쌍 사이에 여러 간선을 허용하는 그래프이다.**

예를 들어 두 도시 사이에 서로 다른 항공편이나 도로가 여러 개 존재한다면 다중 그래프로 표현할 수 있다.

자기 자신으로 연결되는 간선은 **자기 루프(Self-loop)**라고 한다. 자기 루프의 허용 여부는 그래프 모델에 따라 별도로 정한다.

## 그래프와 트리의 관계

**트리(Tree)는 연결되어 있으면서 사이클이 없는 무방향 그래프이다.** 따라서 트리는 그래프의 한 종류이다.

정점이 $n$개인 트리의 간선 수는 항상 $n-1$개이다. 또한 임의의 두 정점 사이에 단순 경로가 정확히 하나 존재한다.

다만 간선 수가 $n-1$개라는 조건만으로 트리라고 판단할 수는 없다. 연결 여부나 사이클 여부를 함께 확인해야 한다.

|구분|일반 그래프| 트리                       |
|---|---|---|
|사이클|존재할 수 있다.| 존재하지 않는다.                |
|연결성|비연결 상태일 수 있다.| 항상 연결되어 있다.              |
|두 정점 사이의 단순 경로|없거나 여러 개일 수 있다.| 정확히 하나이다.                |
|간선 수|종류와 구조에 따라 달라진다.| 정점이 $n$개이면 $n-1$개이다.     |
|계층 구조|반드시 존재하는 것은 아니다.| 루트를 정하면 계층 구조로 표현할 수 있다. |

트리 자체에 루트가 반드시 지정되어 있는 것은 아니다. 하나의 정점을 루트로 선택한 **루트 트리**에서 부모와 자식 관계가 정의된다.

## 그래프를 저장하는 방법

그래프는 연결 관계를 어떻게 저장하느냐에 따라 성능과 메모리 사용량이 달라진다.

### 인접 행렬

**인접 행렬(Adjacency Matrix)은 정점 사이의 연결 여부를 2차원 배열로 저장하는 방식이다.**

앞에서 사용한 그래프의 인접 행렬은 다음과 같다.

```
    A B C D E
A   0 1 1 0 0
B   1 0 0 1 0
C   1 0 0 1 0
D   0 1 1 0 1
E   0 0 0 1 0
```

`matrix[A][B] = 1`이면 A와 B 사이에 간선이 있다는 의미이다. 값이 0이면 간선이 없다는 의미이다.

무방향 그래프에서는 A-B와 B-A가 같은 관계이므로 인접 행렬이 주대각선을 기준으로 대칭이다. 방향 그래프에서는 대칭일 필요가 없다.

인접 행렬의 주요 특징은 다음과 같다.

- 두 정점 사이의 간선 존재 여부를 $O(1)$에 확인할 수 있다.
- 간선의 추가와 삭제를 $O(1)$에 처리할 수 있다.
- 정점 하나의 이웃을 찾으려면 행 전체를 확인하므로 $O(n)$이 필요하다.
- 간선이 적어도 모든 정점 쌍의 공간을 확보하므로 $O(n^2)$의 메모리가 필요하다.

가중치 그래프에서는 1 대신 가중치를 저장할 수 있다. 다만 **가중치가 0인 간선도 가능하므로, 0을 무조건 ‘간선 없음’으로 사용하면 안 된다.** 간선이 없는 상태는 무한대, `null`, 별도의 표시 값 등으로 구분한다.

### 인접 리스트

**인접 리스트(Adjacency List)는 각 정점에 연결된 이웃 정점들을 목록으로 저장하는 방식이다.**

같은 그래프를 인접 리스트로 표현하면 다음과 같다.

```
A: B, C
B: A, D
C: A, D
D: B, C, E
E: D
```

무방향 그래프에서는 간선 하나를 양쪽 정점의 목록에 각각 저장한다. 방향 그래프에서는 일반적으로 출발 정점의 목록에 도착 정점을 저장한다.

가중치 그래프에서는 이웃과 가중치를 함께 저장한다.

```
A: (B, 5), (C, 2)
B: (A, 5), (C, 1)
C: (A, 2), (B, 1)
```

인접 리스트의 주요 특징은 다음과 같다.

- 실제 연결된 이웃만 저장하므로 공간 복잡도는 $O(n+m)$이다.
- 정점 $u$의 이웃을 순회하는 비용은 $O(\deg(u))$이다.
- 일반적인 배열이나 연결 리스트에서는 특정 간선의 존재 여부를 확인하기 위해 이웃 목록을 검색해야 한다.
- 간선이 적은 그래프에서 메모리를 효율적으로 사용한다.

이웃 목록을 해시 집합으로 저장하면 간선 조회의 평균 시간을 줄일 수 있다. 다만 이 경우 메모리 사용량과 순회 순서 등의 특성이 달라진다.

### 간선 리스트

**간선 리스트(Edge List)는 모든 간선을 하나의 목록에 저장하는 방식이다.**

```
(A, B)
(A, C)
(B, D)
(C, D)
(D, E)
```

가중치가 있다면 다음과 같이 저장한다.

```
(출발 정점, 도착 정점, 가중치)
```

특정 정점의 이웃을 찾는 작업에는 비효율적일 수 있지만, 모든 간선을 한 번씩 처리하거나 가중치순으로 정렬하는 작업에는 편리하다.

크루스칼 알고리즘과 벨만–포드 알고리즘에서 자주 사용한다.

### 표현 방식 비교

| 비교 항목        | 인접 행렬               | 일반적인 인접 리스트          | 간선 리스트                  |
| ------------ | ------------------- | -------------------- | ----------------------- |
| 공간 복잡도       | $O(n^2)$이다.         | $O(n+m)$이다.          | 정점 정보를 포함하면 $O(n+m)$이다. |
| 간선 존재 확인     | $O(1)$이다.           | 출발 정점의 이웃 수에 비례한다.   | 최악에는 $O(m)$이다.          |
| 특정 정점의 이웃 탐색 | $O(n)$이다.           | 해당 정점의 이웃 수에 비례한다.   | 일반적으로 $O(m)$이다.         |
| 적합한 작업       | 간선 조회가 잦은 작업에 적합하다. | 이웃 탐색과 그래프 순회에 적합하다. | 전체 간선을 처리하는 작업에 적합하다.   |

**간선이 적고 탐색이 중심인 경우에는 인접 리스트가 일반적인 선택이다.** 정점 수가 작거나 간선이 매우 많고 연결 여부를 자주 확인한다면 인접 행렬도 적합하다.

## 그래프 탐색

**그래프 탐색은 시작 정점에서 간선을 따라 이동하며 도달 가능한 정점들을 방문하는 과정이다.**

대표적인 탐색 알고리즘은 BFS와 DFS이다. 두 알고리즘 모두 사이클이나 중복 방문을 처리하기 위해 방문 여부를 기록하는 것이 중요하다.

### 너비 우선 탐색인 BFS

**BFS(Breadth-First Search)는 시작 정점에서 가까운 정점부터 차례로 방문하는 알고리즘이다.**

일반적으로 **큐(Queue)**를 사용한다. 큐는 먼저 넣은 데이터를 먼저 꺼내는 자료구조이다.

BFS의 진행 과정은 다음과 같다.

1. 시작 정점을 방문 처리하고 큐에 넣는다.
2. 큐에서 정점 하나를 꺼낸다.
3. 해당 정점의 이웃 중 아직 방문하지 않은 정점을 찾는다.
4. 이웃 정점을 방문 처리하고 큐에 넣는다.
5. 큐가 빌 때까지 반복한다.

앞의 그래프에서 A부터 시작하고 이웃을 알파벳순으로 확인하면 방문 순서는 다음과 같다.

```
A → B → C → D → E
```

A에서의 거리에 따라 정점들이 다음 순서로 발견된다.

```
거리 0: A
거리 1: B, C
거리 2: D
거리 3: E
```

**가중치가 없는 그래프에서 BFS는 간선 수가 가장 적은 최단 경로를 구할 수 있다.** 모든 간선의 비용이 같은 경우에도 적용할 수 있다.

방문 처리는 일반적으로 **큐에서 꺼낼 때가 아니라 큐에 넣을 때** 수행한다. 그래야 같은 정점이 여러 경로를 통해 큐에 중복으로 들어가는 것을 막을 수 있다.

### 깊이 우선 탐색인 DFS

**DFS(Depth-First Search)는 하나의 경로를 가능한 한 깊게 탐색한 뒤, 되돌아가 다른 경로를 탐색하는 알고리즘이다.**

일반적으로 **재귀 호출**이나 **스택(Stack)**을 사용한다. 스택은 마지막에 넣은 데이터를 먼저 꺼내는 자료구조이다.

재귀 방식 DFS의 진행 과정은 다음과 같다.

1. 현재 정점을 방문 처리한다.
2. 아직 방문하지 않은 이웃 정점으로 이동한다.
3. 이동한 정점에서 같은 과정을 반복한다.
4. 더 이동할 곳이 없으면 이전 정점으로 돌아온다.
5. 남은 이웃 정점들을 탐색한다.

앞의 그래프에서 A부터 시작하고 이웃을 알파벳순으로 확인하면 방문 순서의 예시는 다음과 같다.

```
A → B → D → C → E
```

DFS는 연결 요소 탐색, 사이클 검사, 위상 정렬 등에 활용된다.

재귀 방식은 간결하지만, 그래프가 매우 깊으면 호출 스택의 한도를 초과할 수 있다. 이런 경우 명시적인 스택을 사용하는 방식이 적합하다.

### BFS와 DFS 비교

|구분|BFS|DFS|
|---|---|---|
|탐색 방식|가까운 정점부터 넓게 탐색한다.|한 경로를 따라 깊게 탐색한다.|
|주요 자료구조|큐를 사용한다.|스택이나 재귀를 사용한다.|
|무가중치 최단 경로|구할 수 있다.|일반적으로 보장하지 않는다.|
|주요 활용|최소 이동 횟수와 거리별 탐색에 활용한다.|사이클 검사와 의존성 분석에 활용한다.|

인접 리스트에서 BFS와 DFS의 시간 복잡도는 모두 $O(n+m)$이다. 정점과 간선을 전체적으로 한 번씩 확인하기 때문이다.

인접 행렬에서는 정점마다 행 전체를 확인하므로 전체 탐색에 $O(n^2)$이 필요하다.

방문 배열과 큐 또는 스택에 필요한 추가 공간은 두 방식 모두 최악의 경우 $O(n)$이다.

### 전체 그래프를 탐색하는 방법

한 정점에서 시작한 탐색은 **그 정점에서 도달 가능한 영역만 방문한다.**

따라서 비연결 그래프 전체를 탐색하려면 모든 정점을 확인하면서, 아직 방문하지 않은 정점마다 BFS나 DFS를 새로 시작해야 한다.

무방향 그래프에서는 이때 새롭게 탐색을 시작한 횟수가 연결 요소의 개수이다.

## 그래프의 대표적인 문제와 알고리즘

### 최단 경로

**최단 경로 문제는 두 정점 사이의 이동 비용이 가장 작은 경로를 찾는 문제이다.**

간선의 조건에 따라 적절한 알고리즘이 달라진다.

|조건|대표 알고리즘|핵심 특징|
|---|---|---|
|가중치가 없거나 모두 같은 경우이다.|BFS를 사용한다.|지나가는 간선 수가 최소인 경로를 찾는다.|
|가중치가 모두 0 이상이다.|다익스트라를 사용한다.|현재까지의 거리가 가장 작은 정점부터 처리한다.|
|음수 가중치가 존재할 수 있다.|벨만–포드를 사용한다.|간선을 반복해서 확인하며 거리를 개선한다.|
|모든 정점 쌍의 최단 거리가 필요하다.|플로이드–워셜을 사용할 수 있다.|중간 정점을 하나씩 고려하며 거리표를 갱신한다.|

**다익스트라 알고리즘은 음수 가중치가 있는 일반적인 그래프에서 올바른 결과를 보장하지 않는다.**

또한 출발점에서 도달 가능한 음수 사이클을 거쳐 목적지까지 갈 수 있다면, 사이클을 반복할수록 비용이 줄어든다. 이 경우 해당 목적지에 대한 유한한 최단 거리가 존재하지 않는다.

최단 경로 자체를 출력하려면 거리뿐 아니라, 각 정점에 도착하기 직전에 거친 정점도 기록한다. 이 정보를 목적지부터 역으로 따라가면 경로를 복원할 수 있다.

### 최소 신장 트리

**신장 트리(Spanning Tree)는 무방향 그래프의 모든 정점을 포함하는 트리이다.**

**최소 신장 트리(Minimum Spanning Tree, MST)는 신장 트리 중 간선 가중치의 합이 가장 작은 트리이다.**

예를 들어 여러 건물을 통신선으로 연결할 때, 모든 건물이 연결되도록 하면서 설치 비용을 최소화하는 문제에 활용한다.

대표적인 알고리즘은 다음과 같다.

- **크루스칼 알고리즘**은 가중치가 작은 간선부터 선택하며 사이클이 생기는 간선을 제외한다.
- **프림 알고리즘**은 현재 선택된 정점 집합과 새로운 정점을 연결하는 가장 저렴한 간선을 선택한다.

최소 신장 트리는 전체 연결 비용을 최소화한다. 특정 출발점에서 각 정점까지의 최단 경로를 보장하는 것은 아니다.

그래프가 비연결 상태이면 전체 정점을 연결하는 신장 트리는 존재하지 않는다. 대신 각 연결 요소의 최소 신장 트리를 모은 최소 신장 숲을 구할 수 있다.

### 위상 정렬

**위상 정렬(Topological Sort)은 방향 그래프의 모든 간선 $u \rightarrow v$에 대해, $u$가 $v$보다 앞에 나오도록 정점을 나열하는 방법이다.**

예를 들어 다음 의존성이 있다면 자료구조를 알고리즘보다 먼저 배치해야 한다.

```
자료구조 → 알고리즘
```

위상 정렬은 DAG에서 가능하다. 사이클이 있으면 모든 의존성을 만족하는 순서를 만들 수 없다.

대표적인 구현 방식은 다음과 같다.

- **진입 차수 방식**은 진입 차수가 0인 정점부터 처리하고, 해당 정점의 간선을 제거한 효과를 반영한다.
- **DFS 방식**은 탐색이 끝나는 순서를 이용해 정렬하며, 사이클 여부도 함께 확인한다.

서로 의존하지 않는 정점들의 순서는 달라질 수 있으므로 위상 정렬 결과는 여러 개일 수 있다.

### 사이클 검사

사이클 검사 방법은 그래프의 방향 여부에 따라 달라진다.

무방향 그래프의 DFS에서는 이미 방문한 이웃을 만났을 때, 그 이웃이 현재 정점의 부모인지 확인한다. 부모로 돌아가는 간선은 무방향 간선의 반대쪽 표현이므로 그것만으로 사이클이라고 판단하면 안 된다.

단순 무방향 그래프에서 부모가 아닌 이미 방문한 이웃을 만나면 사이클이 존재한다.

방향 그래프에서는 방문 여부만으로 판단하기 어렵다. DFS에서 **현재 탐색 중인 경로에 포함된 정점**으로 돌아가는 간선을 만나면 사이클이 존재한다.

### 이분 그래프 검사

**이분 그래프(Bipartite Graph)는 정점들을 두 집합으로 나누고, 모든 간선이 서로 다른 집합의 정점들을 연결하도록 만들 수 있는 그래프이다.**

BFS나 DFS를 이용해 인접한 정점에 서로 다른 두 색을 배정하며 검사할 수 있다.

인접한 두 정점이 같은 색이어야 하는 충돌이 발생하면 이분 그래프가 아니다. 무방향 그래프에서는 홀수 길이의 사이클이 존재하지 않는 것과 이분 그래프인 것이 동치이다.

이분 그래프는 지원자와 일자리, 학생과 프로젝트처럼 서로 다른 두 부류 사이의 연결이나 매칭을 표현하는 데 활용된다.

## 그래프를 다룰 때 자주 하는 실수

### 방문 처리를 빠뜨리는 실수

사이클이 있는 그래프에서 방문 여부를 기록하지 않으면 같은 정점들을 반복해서 방문할 수 있다. 재귀 탐색에서는 무한 재귀나 스택 초과로 이어질 수 있다.

### 무방향 간선을 한쪽에만 저장하는 실수

인접 리스트에서 A-B를 저장한다면 일반적으로 A의 목록에 B를 넣고, B의 목록에도 A를 넣어야 한다.

한쪽만 저장하면 실제로는 방향 그래프처럼 동작한다.

### BFS를 모든 최단 경로 문제에 사용하는 실수

BFS가 보장하는 것은 가중치가 없거나 모든 간선의 비용이 같을 때의 최단 경로이다.

가중치가 다르면 간선 수가 적은 경로의 비용이 더 클 수 있으므로 적합한 알고리즘을 선택해야 한다.

### 시작 정점 하나로 전체 탐색이 끝났다고 판단하는 실수

그래프가 비연결 상태이거나 방향 때문에 도달할 수 없는 정점이 있으면 일부 정점이 방문되지 않는다.

전체 정점을 처리하는 문제에서는 미방문 정점을 추가로 확인해야 한다.

### 탐색 순서를 고정된 결과로 생각하는 실수

BFS와 DFS의 방문 순서는 이웃 정점의 저장 순서와 처리 순서에 따라 달라진다.

문제에서 작은 번호부터 방문하라고 요구한다면 인접 목록을 정렬하는 등의 처리가 필요하다.

## 그래프 문제를 해결하는 판단 순서

그래프 문제에서는 알고리즘을 선택하기 전에 연결의 의미와 조건을 정리하는 것이 중요하다.

1. **정점과 간선의 의미를 정한다.** 무엇을 하나의 상태로 보고, 어떤 경우에 이동이나 관계가 존재하는지 정의한다.
2. **방향 여부를 확인한다.** 관계가 양방향인지 한쪽 방향인지 판단한다.
3. **가중치를 확인한다.** 비용이 모두 같은지, 서로 다른지, 음수가 가능한지 판단한다.
4. **구하려는 결과를 정한다.** 도달 가능성, 최단 거리, 전체 연결 비용, 처리 순서 중 무엇이 필요한지 구분한다.
5. **정점 수와 간선 수를 확인한다.** 입력 크기에 맞는 저장 방식과 알고리즘을 선택한다.
6. **예외 조건을 확인한다.** 비연결 상태, 사이클, 자기 루프, 중복 간선 등의 가능성을 점검한다.

예를 들어 최소 이동 횟수를 구하는 문제라면 BFS를 먼저 고려한다. 비용이 다른 도로의 최소 요금을 구하고 모든 비용이 0 이상이면 다익스트라를 고려한다. 작업의 선후 관계를 만족하는 순서를 구한다면 위상 정렬을 고려한다.

**그래프를 이해하는 핵심은 대상을 정점으로, 관계를 간선으로 모델링하고, 그 연결 구조에 맞는 탐색과 알고리즘을 선택하는 것이다.**
