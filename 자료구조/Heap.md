# 자료구조 Heap이란 무엇인가

**힙(Heap)은 최솟값이나 최댓값을 빠르게 꺼내기 위해 사용하는 자료구조다.** 대표적으로 우선순위 큐, 작업 스케줄링, 상위 K개 데이터 찾기, 힙 정렬에 사용한다.

일반적으로 자료구조에서 힙이라고 하면 **이진 힙(Binary Heap)**을 의미한다. 이진 힙은 다음 두 조건을 만족하는 이진 트리다.

1. 트리의 모양이 **완전 이진 트리**다.
2. 부모와 자식 사이에 **힙 속성**이 성립한다.

---

## 힙의 구조: 완전 이진 트리

### 완전 이진 트리의 의미

완전 이진 트리는 **마지막 레벨을 제외한 모든 레벨이 꽉 차 있고, 마지막 레벨은 왼쪽부터 빈틈없이 채워진 이진 트리**다.

다음은 완전 이진 트리의 예시다.

```
        10
       /  \
     20    15
    / \    /
   30 40  50
```

마지막 레벨의 노드가 왼쪽부터 차례대로 배치되어 있으므로 완전 이진 트리다.

반면 다음 트리는 완전 이진 트리가 아니다.

```
        10
       /  \
     20    15
      \   /
      40 50
```

마지막 레벨에서 왼쪽에 빈자리가 있는데 오른쪽에 노드가 존재하기 때문이다.

### 완전 이진 트리를 사용하는 이유

완전 이진 트리는 노드 수가 증가해도 높이가 빠르게 커지지 않는다.

노드 수가 `n`일 때 높이는 `O(log n)`이다. 따라서 어떤 노드에서 루트까지 올라가거나, 루트에서 가장 아래 레벨까지 내려가는 연산을 `O(log n)` 시간에 처리할 수 있다.

또한 노드 사이에 빈자리가 없으므로 **배열로 저장하기에 적합하다.**

---

## 힙의 규칙: 최소 힙과 최대 힙

힙은 부모와 자식 사이의 대소 관계에 따라 최소 힙과 최대 힙으로 나뉜다.

### 최소 힙

최소 힙에서는 모든 부모의 값이 자식의 값보다 작거나 같다.

```
부모 값 ≤ 자식 값
```

예를 들면 다음과 같다.

```
        10
       /  \
     20    15
    / \   / \
   30 40 50 25
```

각 부모와 자식을 비교하면 다음 규칙이 성립한다.

- `10 ≤ 20`, `10 ≤ 15`가 성립한다.
- `20 ≤ 30`, `20 ≤ 40`이 성립한다.
- `15 ≤ 50`, `15 ≤ 25`가 성립한다.

이 규칙이 모든 부모와 자식 사이에 적용되므로 **루트에는 전체 데이터의 최솟값이 위치한다.**

### 최대 힙

최대 힙에서는 모든 부모의 값이 자식의 값보다 크거나 같다.

```
부모 값 ≥ 자식 값
```

예를 들면 다음과 같다.

```
        90
       /  \
     70    80
    / \   / \
   30 60 50 40
```

최대 힙에서는 **루트에 전체 데이터의 최댓값이 위치한다.**

### 힙은 전체가 정렬된 구조가 아니다

힙에서 보장하는 것은 부모와 자식 사이의 순서다. **형제 노드 사이의 순서나 서로 다른 서브트리에 있는 노드 사이의 순서는 보장하지 않는다.**

앞의 최소 힙에서는 왼쪽 자식이 `20`이고 오른쪽 자식이 `15`여도 문제가 없다. 두 값 모두 부모인 `10`보다 크기 때문이다.

따라서 최소 힙을 배열로 읽었을 때 다음과 같은 순서가 나와도 정상이다.

```
[10, 20, 15, 30, 40, 50, 25]
```

최솟값은 맨 앞에 있지만, 배열 전체가 오름차순으로 정렬된 것은 아니다.

## 힙을 배열로 표현하는 방법

이진 힙은 보통 노드마다 포인터를 두는 방식보다 **배열로 구현한다.**

트리의 노드를 위에서 아래로, 같은 레벨에서는 왼쪽에서 오른쪽으로 저장한다.

```
트리

        10
       /  \
     20    15
    / \   / \
   30 40 50 25
```

```
인덱스:  0   1   2   3   4   5   6
배열:   [10, 20, 15, 30, 40, 50, 25]
```

### 부모와 자식의 인덱스

배열 인덱스를 `0`부터 시작하면 인덱스 `i`에 있는 노드의 위치 관계는 다음과 같다.

|관계|인덱스 계산식|
|---|---|
|부모|`⌊(i - 1) / 2⌋`|
|왼쪽 자식|`2i + 1`|
|오른쪽 자식|`2i + 2`|

예를 들어 인덱스 `1`에 있는 값 `20`의 위치 관계는 다음과 같다.

- 부모의 인덱스는 `0`이므로 부모 값은 `10`이다.
- 왼쪽 자식의 인덱스는 `3`이므로 왼쪽 자식 값은 `30`이다.
- 오른쪽 자식의 인덱스는 `4`이므로 오른쪽 자식 값은 `40`이다.

자식 인덱스가 배열 길이 이상이면 해당 자식은 존재하지 않는다. 루트인 인덱스 `0`에는 부모가 없다.

이 방식은 부모와 자식을 산술 연산으로 찾을 수 있어 별도의 연결 포인터가 필요하지 않다.

## 삽입: 마지막에 추가한 뒤 위로 올린다

최소 힙에 새 값을 삽입하는 과정은 다음과 같다.

1. 배열의 마지막에 새 값을 추가한다.
2. 새 값과 부모 값을 비교한다.
3. 새 값이 부모보다 작으면 두 값을 교환한다.
4. 힙 속성이 만족되거나 루트에 도달할 때까지 반복한다.

이 과정을 **상향 조정(sift up)**이라고 한다.

### 삽입 예시

다음 최소 힙에 `12`를 삽입한다고 가정한다.

```
[10, 20, 15, 30, 40, 50, 25]
```

**① 마지막 위치에 `12`를 추가한다.**

```
[10, 20, 15, 30, 40, 50, 25, 12]
```

트리에서 `12`는 `30`의 왼쪽 자식이 된다.

```
          10
         /  \
       20    15
      / \   / \
     30 40 50 25
    /
   12
```

**② 부모인 `30`과 비교하고 교환한다.**

`12 < 30`이므로 두 값을 교환한다.

```
[10, 20, 15, 12, 40, 50, 25, 30]
```

**③ 새로운 부모인 `20`과 비교하고 교환한다.**

`12 < 20`이므로 두 값을 교환한다.

```
[10, 12, 15, 20, 40, 50, 25, 30]
```

**④ 부모인 `10`과 비교하고 종료한다.**

`12 ≥ 10`이므로 힙 속성이 만족된다.

### 삽입의 시간 복잡도

최악의 경우 마지막 레벨에서 루트까지 올라간다. 트리 높이가 `O(log n)`이므로 삽입의 핵심 연산은 **`O(log n)`**이다.

동적 배열의 용량 확장이 발생하는 개별 삽입은 배열 복사 때문에 `O(n)`이 걸릴 수 있다. 일반적인 힙의 삽입 복잡도는 용량 확장 비용을 분할 상환하여 `O(log n)`으로 설명한다.

## 루트 제거: 마지막 값을 루트로 옮긴 뒤 아래로 내린다

힙에서 가장 대표적인 제거 연산은 루트 제거다.

최소 힙에서는 최솟값을 꺼내고, 최대 힙에서는 최댓값을 꺼낸다. 보통 이를 `extract` 또는 `pop`이라고 한다.

최소 힙의 루트 제거 과정은 다음과 같다.

1. 루트 값을 반환할 값으로 보관한다.
2. 마지막 노드를 제거하고, 그 값을 루트 위치에 놓는다.
3. 현재 노드와 자식들을 비교한다.
4. 자식 중 더 작은 값이 현재 값보다 작으면 교환한다.
5. 힙 속성이 만족되거나 자식이 없어질 때까지 반복한다.

이 과정을 **하향 조정(sift down)**이라고 한다.

### 루트 제거 예시

다음 최소 힙에서 최솟값 `10`을 꺼낸다고 가정한다.

```
[10, 20, 15, 30, 40, 50, 25]
```

**① 마지막 값 `25`를 루트로 옮긴다.**

```
[25, 20, 15, 30, 40, 50]
```

```
        25
       /  \
     20    15
    / \   /
   30 40 50
```

**② 두 자식 중 더 작은 값 `15`와 교환한다.**

```
[15, 20, 25, 30, 40, 50]
```

```
        15
       /  \
     20    25
    / \   /
   30 40 50
```

**③ 새로운 위치에서 자식과 비교한다.**

`25`의 자식은 `50`이고 `25 ≤ 50`이므로 종료한다.

반환한 값은 `10`이며, 남은 데이터는 최소 힙 속성을 유지한다.

### 반드시 더 작은 자식을 선택해야 하는 이유

최소 힙에서 현재 값이 두 자식보다 모두 크다면 더 작은 자식과 교환해야 한다.

앞의 예시에서 `25`를 `20`과 교환하면 루트가 `20`이지만 오른쪽 자식은 `15`가 된다. 그러면 `20 ≤ 15`가 성립하지 않아 힙 속성이 깨진다.

최대 힙에서는 반대로 **더 큰 자식**을 선택한다.

### 루트 제거의 시간 복잡도

루트에서 마지막 레벨까지 내려가는 경우가 가장 오래 걸린다. 따라서 시간 복잡도는 **`O(log n)`**이다.

원소가 하나뿐이라면 그 원소를 제거하고 빈 힙으로 만든다.

## 힙 구성: 기존 배열을 힙으로 바꾼다

이미 데이터가 배열에 들어 있다면 이를 힙으로 만드는 방법은 크게 두 가지다.

### 방법 1: 하나씩 삽입한다

빈 힙을 만든 뒤 데이터를 하나씩 삽입한다.

각 삽입에 최대 `O(log n)`이 걸리므로 전체 시간은 **`O(n log n)`**이다.

### 방법 2: 아래쪽 부모부터 하향 조정한다

기존 배열에서 마지막 부모 노드부터 루트 방향으로 이동하며 하향 조정을 수행한다.

인덱스를 `0`부터 사용할 때 마지막 부모 노드의 인덱스는 다음과 같다.

```
⌊n / 2⌋ - 1
```

그 뒤의 노드들은 모두 자식이 없는 잎 노드다. 잎 노드 하나만 놓고 보면 이미 힙 속성을 만족한다.

따라서 자식 쪽을 먼저 정리하고, 점차 위쪽 부모를 정리하면 전체 배열이 힙이 된다. 이 방식을 **상향식 힙 구성(bottom-up heap construction)**이라고 하며, 많은 구현에서 `heapify`라고 부른다.

### 전체 시간 복잡도가 O(n)인 이유

모든 노드가 트리 높이만큼 이동하는 것은 아니다.

- 전체 노드의 약 절반인 잎 노드는 내려갈 필요가 없다.
- 약 4분의 1에 해당하는 노드는 최대 한 단계만 내려간다.
- 약 8분의 1에 해당하는 노드는 최대 두 단계만 내려간다.
- 여러 단계를 내려갈 수 있는 상위 노드는 상대적으로 적다.

전체 작업량은 다음 합으로 생각할 수 있다.

```
n × (1/4 + 2/8 + 3/16 + …)
```

괄호 안의 합이 상수에 수렴하므로 전체 시간 복잡도는 **`O(n)`**이다.

따라서 기존 데이터를 한꺼번에 힙으로 만들 때는 상향식 구성이 효율적이다.

---

## 주요 연산의 시간 복잡도

일반적인 이진 힙의 복잡도는 다음과 같다.

|연산|시간 복잡도|
|---|---|
|루트 조회|`O(1)`|
|삽입|`O(log n)`|
|루트 제거|`O(log n)`|
|기존 배열의 상향식 힙 구성|`O(n)`|
|임의의 값 검색|`O(n)`|
|위치를 알고 있는 원소의 제거|`O(log n)`|
|위치를 알고 있는 원소의 우선순위 변경|`O(log n)`|
|전체 데이터 저장 공간|`O(n)`|

**임의의 원소를 제거하거나 수정하는 작업은 해당 원소의 위치를 아는지가 중요하다.**

위치를 알고 있으면 교환 후 상향 조정이나 하향 조정으로 복구할 수 있다. 위치를 모르면 먼저 검색해야 하므로 전체 작업에 `O(n)`이 걸릴 수 있다.

또한 특정 노드가 왼쪽 자식보다 크거나 작다는 사실만으로 다른 서브트리의 값을 판단할 수 없으므로, 일반적인 값 검색에는 힙의 장점이 크지 않다.

## 힙과 우선순위 큐의 관계

**우선순위 큐는 동작을 정의하는 개념이고, 힙은 이를 구현하는 자료구조다.**

일반적인 큐는 먼저 들어온 데이터를 먼저 꺼내는 FIFO 방식이다. 우선순위 큐는 들어온 순서보다 우선순위를 기준으로 데이터를 꺼낸다.

예를 들어 처리할 작업이 다음과 같다고 가정한다.

|작업|우선순위 값|
|---|---|
|일반 작업|5|
|긴급 작업|1|
|백그라운드 작업|10|

숫자가 작을수록 먼저 처리하도록 정의하면 최소 힙으로 구현할 수 있다.

이 경우 입력 순서와 관계없이 긴급 작업, 일반 작업, 백그라운드 작업 순서로 꺼낸다.

다만 우선순위 큐를 반드시 힙으로 구현해야 하는 것은 아니다. 배열, 연결 리스트, 균형 이진 탐색 트리 등으로도 구현할 수 있으며, 삽입과 추출의 요구 조건에 따라 구현을 선택한다.

### 우선순위가 같을 때의 처리

일반적인 이진 힙은 같은 우선순위를 가진 데이터의 입력 순서를 보장하지 않는다.

같은 우선순위에서는 먼저 들어온 작업을 먼저 처리해야 한다면 다음과 같이 비교 기준을 구성한다.

```
(우선순위, 입력 순번, 실제 데이터)
```

우선순위를 먼저 비교하고, 우선순위가 같으면 입력 순번을 비교하도록 만든다.

## 힙 정렬

힙 정렬은 힙의 루트에 최댓값 또는 최솟값이 놓인다는 성질을 이용하는 정렬 알고리즘이다.

배열을 제자리에서 오름차순으로 정렬할 때는 보통 최대 힙을 사용한다.

1. 배열 전체를 최대 힙으로 만든다.
2. 루트의 최댓값과 힙의 마지막 원소를 교환한다.
3. 마지막 위치를 정렬 완료 영역으로 제외한다.
4. 남은 힙의 루트에 하향 조정을 적용한다.
5. 힙에 원소가 하나 남을 때까지 반복한다.

매번 남은 데이터의 최댓값이 배열 뒤쪽에 확정되므로 최종적으로 오름차순 정렬이 된다.

### 힙 정렬의 특징

- 상향식 힙 구성에는 `O(n)`이 걸린다.
- 최댓값을 반복해서 배치하는 과정에는 `O(n log n)`이 걸린다.
- 전체 시간 복잡도는 **`O(n log n)`**이다.
- 반복문으로 하향 조정을 구현하면 추가 공간을 **`O(1)`**로 유지할 수 있다.
- 일반적인 제자리 힙 정렬은 같은 키를 가진 원소의 상대 순서를 보장하지 않는 불안정 정렬이다.

최소 힙에서 최솟값을 계속 꺼내 별도 배열에 담는 방식으로도 오름차순 결과를 만들 수 있다. 다만 이 경우 결과를 담을 추가 공간이 필요하다.

## 힙과 이진 탐색 트리의 차이

힙과 이진 탐색 트리는 모두 이진 트리 형태로 표현할 수 있지만, 유지하는 규칙과 목적이 다르다.

|비교 항목|이진 힙|이진 탐색 트리|
|---|---|---|
|핵심 규칙|부모와 자식 사이의 대소 관계|왼쪽·오른쪽 서브트리의 키 범위|
|모양|완전 이진 트리|구현에 따라 달라지는 구조|
|주요 목적|최솟값 또는 최댓값의 반복 추출|키 검색과 정렬된 순서의 탐색|
|임의의 값 검색|`O(n)`|균형을 유지하면 `O(log n)`|
|정렬된 순서의 순회|일반 순회로 보장되지 않는 구조|중위 순회로 얻는 구조|

최소 힙의 규칙은 다음과 같다.

```
부모 ≤ 왼쪽 자식
부모 ≤ 오른쪽 자식
```

중복 키가 없는 이진 탐색 트리의 규칙은 다음과 같다.

```
왼쪽 서브트리의 모든 키 < 현재 키 < 오른쪽 서브트리의 모든 키
```

따라서 특정 값을 자주 검색해야 한다면 균형 이진 탐색 트리가 더 적합할 수 있다. 매번 가장 작은 값이나 가장 큰 값을 꺼내야 한다면 힙이 적합하다.

## 힙이 유용한 대표적인 문제

### 상위 K개의 큰 값 찾기

데이터 `n`개 중 가장 큰 값 `k`개를 유지하려면 **크기가 최대 `k`인 최소 힙**을 사용할 수 있다.

1. 힙에 원소가 `k`개 미만이면 새 값을 삽입한다.
2. 원소가 `k`개라면 새 값과 루트를 비교한다.
3. 새 값이 루트보다 크면 루트를 제거하고 새 값을 넣는다.
4. 새 값이 루트 이하라면 건너뛴다.

이때 루트는 현재 보관 중인 상위 K개 값 가운데 가장 작은 값이다. 따라서 새로운 값이 상위 K개에 들어갈 수 있는지 빠르게 판단할 수 있다.

`k ≥ 2`일 때 전체 처리 시간은 `O(n log k)`이고, 추가 공간은 `O(k)`이다.

### 여러 정렬된 목록 합치기

정렬된 목록이 여러 개 있다면 각 목록에서 아직 사용하지 않은 첫 번째 원소를 최소 힙에 넣는다.

힙에서 최솟값을 꺼낸 뒤, 그 원소가 속한 목록의 다음 원소를 다시 넣는다. 이 과정을 반복하면 전체 목록을 정렬된 순서로 합칠 수 있다.

목록 수가 `k`개이고 전체 원소 수가 `N`개라면 일반적으로 `O(N log k)` 시간에 처리할 수 있다.

### 실시간 중앙값 관리

최대 힙과 최소 힙을 함께 사용하면 데이터가 계속 들어오는 상황에서 중앙값을 관리할 수 있다.

- 작은 값 절반은 최대 힙에 저장한다.
- 큰 값 절반은 최소 힙에 저장한다.
- 두 힙의 크기 차이가 최대 1이 되도록 조정한다.

두 힙의 루트에 중앙값 후보가 위치하므로, 원소 삽입은 `O(log n)`, 중앙값 조회는 `O(1)`에 처리할 수 있다.

### 그래프 알고리즘과 작업 스케줄링

힙은 다익스트라 알고리즘에서 현재 거리가 가장 짧은 후보를 고르는 데 사용한다. 프림 알고리즘에서는 다음에 고려할 최소 비용 간선을 선택하는 데 활용한다.

작업 스케줄러에서는 실행 시각이 가장 빠른 작업이나 우선순위가 가장 높은 작업을 선택하는 데 사용한다.

## 자주 헷갈리는 부분

### 최소 힙에서 최댓값도 바로 찾을 수 있는가

최소 힙이 빠르게 제공하는 것은 최솟값이다. 최댓값의 위치는 따로 유지하지 않으면 일반적으로 탐색해야 한다.

최댓값은 잎 노드 중에 존재하지만 잎 노드의 수 자체가 `O(n)`이므로, 최댓값 검색의 최악 시간 복잡도도 `O(n)`이다.

### 중복된 값을 넣을 수 있는가

힙에는 중복된 값을 넣을 수 있다.

최소 힙의 조건이 `부모 < 자식`이 아니라 **`부모 ≤ 자식`** 이기 때문이다. 최대 힙도 같은 이유로 중복 값을 허용한다.

### 배열을 앞에서부터 읽으면 정렬된 결과가 나오는가

힙의 배열을 그대로 읽으면 정렬된 결과가 나오지 않는다.

정렬된 결과가 필요하다면 루트를 반복해서 꺼내거나 힙 정렬을 수행해야 한다.

### 원소의 값을 직접 바꿔도 되는가

힙 안의 값을 바꾸면 부모나 자식과의 관계가 깨질 수 있다.

따라서 값을 변경한 뒤에는 필요에 따라 상향 조정이나 하향 조정을 수행해야 한다. 위치를 빠르게 찾아 수정해야 하는 상황에서는 별도의 인덱스 관리가 필요할 수 있다.

### 메모리의 힙 영역과 같은 개념인가

자료구조인 힙과 프로그램의 동적 메모리를 저장하는 힙 영역은 서로 다른 개념이다.

이름은 같지만, 메모리의 힙 영역이 여기서 설명한 이진 힙의 규칙으로 관리된다는 뜻은 아니다.
