## Tree란 무엇인가

**트리(Tree)는 데이터 사이의 계층 관계를 표현하는 자료구조다.** 하나의 시작점에서 여러 갈래로 뻗어나가는 구조를 가지며, 컴퓨터에서는 보통 뿌리를 위에 두고 가지가 아래로 내려가도록 표현한다.

배열이나 연결 리스트가 데이터를 일렬로 배치한다면, 트리는 데이터를 부모와 자식의 관계로 배치한다. 따라서 조직도, 폴더 구조, 댓글과 답글처럼 계층이 있는 데이터를 표현하기에 적합하다.

다음은 간단한 트리의 예시다.

```
          A
        /   \
       B     C
      / \     \
     D   E     F
```

이 트리에서 A는 시작점이며, B와 C는 A 아래에 연결된 데이터다. D와 E는 B 아래에 연결되어 있고, F는 C 아래에 연결되어 있다.

## 트리를 구성하는 기본 용어

### 노드와 간선

**노드(Node)는 트리에 저장되는 각각의 데이터 단위다.** 위 그림에서 A, B, C, D, E, F가 모두 노드다.

**간선(Edge)은 노드와 노드를 연결하는 선이다.** A와 B를 연결하는 선이나 B와 D를 연결하는 선이 간선에 해당한다.

노드는 값을 저장할 수 있으며, 구현 방식에 따라 자식 노드를 가리키는 참조나 포인터도 함께 저장한다.

### 루트 노드

**루트 노드(Root Node)는 트리의 가장 위에 있는 시작 노드다.**

위 그림에서는 A가 루트다. 루트는 부모가 없으며, 하나의 비어 있지 않은 트리에는 루트가 하나만 존재한다.

### 부모, 자식, 형제

노드 사이의 바로 위아래 관계를 부모와 자식 관계라고 한다.

- A는 B와 C의 부모 노드다.
- B와 C는 A의 자식 노드다.
- B와 C는 같은 부모를 가진 형제 노드다.
- D와 E는 B의 자식이면서 서로 형제 노드다.

루트를 제외한 모든 노드는 부모를 정확히 하나 가진다. 하나의 부모는 트리의 종류에 따라 여러 자식을 가질 수 있다.

### 리프 노드와 내부 노드

**리프 노드(Leaf Node)는 자식이 없는 노드다.** 말단 노드라고도 한다.

위 그림에서는 D, E, F가 리프 노드다.

**내부 노드(Internal Node)는 자식이 하나 이상 있는 노드다.** 위 그림에서는 A, B, C가 내부 노드다.

### 조상과 자손

어떤 노드에서 부모 방향으로 계속 올라갔을 때 만나는 노드를 조상이라고 한다. 자식 방향으로 내려갔을 때 만나는 노드를 자손이라고 한다.

- D의 조상은 B와 A다.
- B의 자손은 D와 E다.
- A의 자손은 B, C, D, E, F다.

별도의 정의가 없다면 일반적으로 자기 자신은 자신의 조상이나 자손에 포함하지 않는다.

### 서브트리

**서브트리(Subtree)는 특정 노드와 그 노드의 모든 자손으로 이루어진 작은 트리다.**

B를 루트로 하는 서브트리는 다음과 같다.

```
       B
      / \
     D   E
```

트리의 일부가 다시 트리가 된다는 성질 때문에 트리는 재귀적으로 다루기 좋은 자료구조다.

### 깊이와 높이

**깊이(Depth)는 루트에서 특정 노드까지 내려가는 데 필요한 간선의 수다.**

위 예시에서 각 노드의 깊이는 다음과 같다.

- A의 깊이는 0이다.
- B와 C의 깊이는 1이다.
- D, E, F의 깊이는 2다.

**높이(Height)는 특정 노드에서 가장 멀리 있는 리프까지 내려가는 경로의 간선 수다.** 트리 전체의 높이는 루트 노드의 높이다.

- D, E, F의 높이는 0이다.
- B와 C의 높이는 1이다.
- A의 높이와 트리 전체의 높이는 2다.

자료에 따라 높이를 간선 수가 아닌 노드 수로 정의하기도 한다. 이 설명에서는 **루트의 깊이를 0, 리프의 높이를 0**으로 정의한다.

### 차수

**노드의 차수(Degree)는 그 노드가 가진 자식의 수다.**

- A의 차수는 2다.
- C의 차수는 1이다.
- D의 차수는 0이다.

트리의 차수는 모든 노드의 차수 중 가장 큰 값이다. 위 트리의 차수는 2다.

## 트리의 핵심 성질

### 연결되어 있고 순환이 없다

그래프 이론에서 트리는 **연결되어 있으면서 순환이 없는 무방향 그래프**다. 자료구조에서는 여기에 루트를 정하고 부모와 자식의 관계를 부여하는 경우가 많다.

순환이 없다는 것은 간선을 따라 이동했을 때 같은 간선을 되짚지 않고 출발점으로 돌아오는 경로가 없다는 뜻이다.

따라서 자손을 따라 계속 내려가다가 다시 자신의 조상으로 연결되는 구조는 트리가 아니다.

### 두 노드 사이의 경로가 유일하다

트리에서는 어떤 두 노드를 선택하더라도 그 사이를 연결하는 단순 경로가 정확히 하나 존재한다.

앞의 예시에서 D에서 F로 이동하는 경로는 다음과 같다.

```
D → B → A → C → F
```

두 노드 사이에 서로 다른 경로가 존재한다면 순환이 생기므로 트리가 될 수 없다.

### 노드가 n개라면 간선은 n−1개다

비어 있지 않은 트리에서 노드의 수가 `n`이라면 간선의 수는 항상 `n−1`개다.

루트를 제외한 모든 노드가 부모와 연결되는 간선을 하나씩 가지기 때문이다.

다만 **간선이 n−1개라는 조건만으로 트리라고 판단할 수는 없다.** 모든 노드가 연결되어 있는지도 함께 확인해야 한다.

## 트리의 주요 종류

### 일반 트리

일반 트리는 각 노드가 가질 수 있는 자식의 수에 고정된 제한이 없는 트리다.

```
          A
       /  |  \
      B   C   D
     / \     /|\
    E   F   G H I
```

폴더 구조나 조직도처럼 하나의 항목 아래에 여러 항목이 연결되는 경우에 적합하다.

### 이진 트리

**이진 트리(Binary Tree)는 각 노드가 자식을 최대 두 개까지 가지는 트리다.**

두 자식은 왼쪽 자식과 오른쪽 자식으로 구분한다. 왼쪽 자식만 있는 경우와 오른쪽 자식만 있는 경우는 서로 다른 구조로 취급한다.

```
       A
      / \
     B   C
      \
       D
```

이진 트리라는 조건은 자식 수에 관한 조건이다. **값이 정렬되어 있다는 의미는 아니다.**

### 정 이진 트리

정 이진 트리라고 부르는 Full Binary Tree는 모든 노드의 자식 수가 0개 또는 2개인 이진 트리다.

```
       A
      / \
     B   C
        / \
       D   E
```

자식이 하나만 있는 노드는 허용하지 않는다. 모든 리프가 같은 깊이에 있을 필요는 없다.

### 완전 이진 트리

**완전 이진 트리(Complete Binary Tree)는 마지막 레벨을 제외한 모든 레벨이 채워져 있고, 마지막 레벨은 왼쪽부터 빈틈없이 채워진 이진 트리다.**

```
          A
        /   \
       B     C
      / \   /
     D   E F
```

마지막 레벨에서 오른쪽에 빈자리가 있는 것은 허용한다. 그러나 왼쪽 자리가 비어 있는데 그보다 오른쪽 자리가 채워져 있으면 완전 이진 트리가 아니다.

완전 이진 트리는 배열로 저장하기 편리하며, 이진 힙에서 사용하는 구조다.

### 포화 이진 트리

**포화 이진 트리(Perfect Binary Tree)는 모든 내부 노드가 자식을 두 개 가지고, 모든 리프가 같은 깊이에 있는 이진 트리다.**

```
          A
        /   \
       B     C
      / \   / \
     D   E F   G
```

높이가 `h`인 포화 이진 트리의 전체 노드 수는 다음과 같다.

```
전체 노드 수 = 2^(h+1) − 1
리프 노드 수 = 2^h
```

예를 들어 높이가 2라면 전체 노드는 7개이고, 리프 노드는 4개다.

### 편향 트리와 균형 트리

편향 트리(Skewed Tree)는 노드가 한쪽 방향으로 길게 이어지는 트리다.

```
A
 \
  B
   \
    C
     \
      D
```

이 구조는 연결 리스트와 비슷해진다. 노드 수가 `n`개라면 높이가 `n−1`이 될 수 있다.

균형 트리(Balanced Tree)는 트리의 높이가 지나치게 커지지 않도록 구조를 유지하는 트리다. 균형을 판단하는 구체적인 규칙은 트리 종류에 따라 다르다.

탐색용 트리에서는 균형을 유지하여 높이를 `O(log n)`으로 제한하는 것이 중요하다.

## 목적에 따라 사용하는 대표적인 트리

### AVL 트리와 레드-블랙 트리

AVL 트리와 레드-블랙 트리는 삽입과 삭제 이후에도 높이가 `O(log n)`으로 유지되도록 조정하는 BST다.

AVL 트리는 각 노드에서 왼쪽과 오른쪽 서브트리의 높이 차이가 최대 1이 되도록 유지한다.

레드-블랙 트리는 노드에 색을 부여하고, 색과 경로에 관한 규칙을 유지하여 높이가 지나치게 커지는 것을 방지한다.

두 구조 모두 회전(Rotation) 등의 연산으로 트리의 연결 관계를 조정한다. 회전은 BST의 정렬 관계를 유지하면서 높이와 균형을 개선하는 연산이다.

### 힙

**이진 힙(Binary Heap)은 완전 이진 트리 구조와 부모·자식 사이의 우선순위 규칙을 가진 자료구조다.**

최소 힙에서는 부모의 값이 자식의 값보다 작거나 같다. 최대 힙에서는 부모의 값이 자식의 값보다 크거나 같다.

최소 힙의 예시는 다음과 같다.

```
          1
        /   \
       3     2
      / \   /
     7   5 4
```

최소 힙의 루트에는 전체 최솟값이 저장된다. 그러나 왼쪽 서브트리와 오른쪽 서브트리 사이에는 BST와 같은 정렬 규칙이 없다.

따라서 힙은 최솟값이나 최댓값을 반복해서 꺼내는 우선순위 큐에 적합하다. 특정 값의 존재 여부를 빠르게 검색하기 위한 구조는 아니다.

이진 힙에서 루트 값 확인은 `O(1)`이며, 삽입과 루트 제거는 `O(log n)`이다.

### 트라이

**트라이(Trie)는 문자열을 문자 또는 문자열 조각의 경로로 저장하는 트리다.**

`cat`, `car`, `dog`를 저장하면 다음과 같은 형태가 된다.

```
루트
├─ c
│  └─ a
│     ├─ t
│     └─ r
└─ d
   └─ o
      └─ g
```

`cat`과 `car`는 공통 접두사인 `ca`의 경로를 공유한다. 실제 구현에서는 단어가 끝나는 위치를 표시해야 완전한 단어와 접두사를 구분할 수 있다.

트라이는 자동완성이나 접두사 검색에 유용하다. 각 단계의 자식 탐색을 상수 시간에 처리하는 구현에서는 길이가 `L`인 문자열의 탐색에 `O(L)`이 걸린다.

### B-트리와 B+트리

B-트리와 B+트리는 한 노드에 여러 키를 저장하고 여러 자식을 연결하는 균형 탐색 트리다.

한 노드가 많은 정보를 담으므로 트리 높이를 낮게 유지할 수 있다. 디스크나 저장 장치에서 데이터를 읽는 횟수를 줄이는 데 유리하다.

B+트리의 대표적인 구조에서는 내부 노드가 탐색을 안내하고, 실제 데이터 항목이나 그 위치를 리프 노드에 저장한다. 리프 노드들이 연결되어 있어 범위 검색에도 적합하다.

이러한 특성 때문에 데이터베이스 인덱스와 저장 시스템에 널리 활용한다.

## 트리를 메모리에 표현하는 방법

### 참조나 포인터로 연결하는 방식

이진 트리의 노드는 보통 다음 정보를 가진다.

```
Node
├─ value
├─ left
└─ right
```

`value`는 저장할 값이며, `left`와 `right`는 각각 왼쪽 자식과 오른쪽 자식을 가리킨다. 자식이 없으면 해당 참조는 비어 있다.

일반 트리에서는 자식 수가 가변적이므로 자식 참조들을 배열이나 리스트에 저장할 수 있다.

이 방식은 다양한 모양의 트리를 표현하기 쉽지만, 노드마다 연결 정보를 저장하는 공간이 필요하다.

### 배열로 저장하는 방식

완전 이진 트리는 배열로 표현하기에 적합하다.

```
트리의 레벨 순서: A, B, C, D, E, F, G
배열:           [A, B, C, D, E, F, G]
```

인덱스를 0부터 시작하면 인덱스 `i`에 있는 노드의 위치 관계는 다음과 같다.

```
왼쪽 자식 인덱스 = 2i + 1
오른쪽 자식 인덱스 = 2i + 2
부모 인덱스 = floor((i − 1) / 2)
```

자식 인덱스가 배열 길이를 벗어나면 해당 자식은 존재하지 않는다. 부모 계산식은 루트를 제외한 노드에 적용한다.

이 방식은 별도의 자식 포인터 없이 위치를 계산할 수 있다. 반면 빈자리가 많은 불규칙한 트리는 배열로 표현할 때 공간이 낭비될 수 있다.

## 트리의 핵심

트리는 계층 관계를 표현하는 기본 구조이며, 구체적인 규칙을 추가하면 다양한 목적의 자료구조가 된다.

- 계층 데이터를 표현할 때는 일반 트리를 사용할 수 있다.
- 값의 대소 관계로 탐색할 때는 BST를 사용할 수 있다.
- 탐색 성능을 안정적으로 유지하려면 균형 탐색 트리가 적합하다.
- 최솟값이나 최댓값을 반복해서 꺼낼 때는 힙이 적합하다.
- 문자열의 접두사를 검색할 때는 트라이가 적합하다.
- 저장 장치 접근과 범위 검색을 고려할 때는 B-트리 계열이 적합하다.

트리를 이해할 때는 **노드 사이의 관계, 값을 배치하는 규칙, 트리의 높이, 방문 순서**를 함께 살펴보아야 한다. 같은 트리 형태라도 어떤 규칙을 적용하느냐에 따라 지원하는 연산과 성능이 달라진다.
