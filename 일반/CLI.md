# CLI란

**CLI(Command-Line Interface)는 명령어를 입력해 컴퓨터나 프로그램을 조작하는 방식**이다.

평소에는 폴더를 더블클릭하거나 버튼을 눌러 컴퓨터를 사용한다. CLI에서는 같은 작업을 글자로 된 명령어로 지시한다.

예를 들어 새로운 폴더를 만들 때 다음과 같이 입력한다.

```
mkdir my-project
```

`mkdir`는 “폴더를 만들어라”, `my-project`는 “폴더 이름을 이렇게 정해라”라는 뜻이다.

---

## CLI와 GUI의 차이

CLI와 자주 비교되는 개념은 **GUI(Graphical User Interface)**이다. GUI는 창, 아이콘, 버튼 등 화면의 그래픽 요소를 조작하는 방식이다.

|구분|CLI|GUI|
|---|---|---|
|조작 방법|명령어 입력|클릭, 터치, 드래그|
|대표적인 사용 장면|터미널에서 파일 이동|탐색기나 Finder에서 파일 이동|
|처음 배우기|명령어와 문법을 익혀야 함|화면을 보면서 시작하기 쉬움|
|반복 작업|스크립트로 자동화하기 좋음|프로그램에 따라 반복 조작이 필요함|
|작업 기록|명령어를 저장하고 공유하기 쉬움|조작 과정을 별도로 기록해야 할 수 있음|
|시각적 작업|이미지나 레이아웃 확인에 한계가 있음|사진 편집, 디자인 등에 적합|

예를 들어 파일 하나를 이동할 때는 마우스가 편할 수 있다. 반면 **파일 1,000개를 일정한 규칙에 따라 분류하는 작업**은 CLI와 스크립트를 사용하면 훨씬 효율적일 수 있다.

두 방식은 경쟁 관계라기보다, 작업에 맞춰 함께 사용하는 도구이다.

## 터미널·셸·CLI 차이

처음 접할 때 가장 헷갈리는 부분이다. 세 용어는 관련되어 있지만 같은 뜻은 아니다.

### 터미널: 명령어를 입력하고 결과를 보는 창

현대적인 개발 환경에서 “터미널”은 대체로 텍스트를 입력하고 출력을 보여주는 프로그램을 뜻한다.

예를 들면 다음과 같다.

- macOS의 **터미널 앱**
- Windows의 **Windows Terminal**
- Visual Studio Code에 내장된 **터미널 패널**

### 셸: 입력한 명령어를 해석하는 프로그램

셸은 터미널에 입력한 명령어를 해석하고, 해당 작업이나 프로그램을 실행한다.

대표적인 셸은 다음과 같다.

- **Bash**
- **Zsh**
- **PowerShell**
- **cmd.exe**

셸마다 문법과 기본 명령어가 다를 수 있다. 따라서 인터넷에서 발견한 명령어가 모든 환경에서 그대로 작동하는 것은 아니다.

### CLI: 프로그램을 명령어로 사용하는 인터페이스

CLI는 특정 창이나 프로그램 하나의 이름이 아니라 **조작 방식**을 가리킨다.

예를 들어 Git은 다음과 같은 CLI를 제공한다.

```
git status
```

이 명령어는 현재 Git 저장소의 변경 상태를 보여준다.

세 개념을 연결하면 다음과 같다.

> **터미널**에 명령어를 입력하면 → **셸**이 이를 해석하고 → 해당 **CLI 프로그램**을 실행한다.

다만 `cd`처럼 외부 프로그램을 실행하지 않고 셸 자체가 처리하는 명령어도 있다.

## 명령어 구조

많은 CLI 명령어는 다음 구조를 따른다.

```
프로그램 이름 [하위 명령어] [옵션] [인자]
```

여기서 대괄호는 설명을 위한 표기이며, 해당 부분이 선택 사항이라는 뜻이다. 실제로 대괄호까지 입력하는 것은 아니다.

예를 들어 다음 명령어를 살펴본다.

```
python --version
```

|구성 요소|값|의미|
|---|---|---|
|프로그램 이름|`python`|Python 실행|
|옵션|`--version`|버전 정보를 보여 달라는 요청|

다른 예시이다.

```
git log --oneline -5
```

|구성 요소|값|의미|
|---|---|---|
|프로그램 이름|`git`|Git 실행|
|하위 명령어|`log`|커밋 기록 조회|
|옵션|`--oneline`|각 기록을 한 줄로 표시|
|옵션|`-5`|최근 5개만 표시|

### 옵션과 인자의 차이

- **옵션**은 동작 방식을 지정한다. 예: 자세히 출력하기, 특정 형식으로 표시하기.
- **인자**는 작업 대상을 지정한다. 예: 파일 이름, 폴더 경로.

```
ls -l Documents
```

이 예시에서 `-l`은 상세한 형식으로 보여 달라는 옵션이고, `Documents`는 목록을 확인할 대상 폴더이다.

옵션은 보통 `-l`, `--version`처럼 작성하지만, **정확한 문법은 프로그램마다 다르다.**

## 기본 명령어

아래 예시는 **macOS·Linux의 Bash 또는 Zsh 기준**이다. Windows에서도 WSL 등 유사한 환경에서는 사용할 수 있지만, PowerShell이나 명령 프롬프트에서는 일부 명령어와 문법이 다르다.

|명령어|하는 일|예시|
|---|---|---|
|`pwd`|현재 위치 확인|`pwd`|
|`ls`|파일과 폴더 목록 확인|`ls`|
|`cd`|작업할 폴더로 이동|`cd Documents`|
|`mkdir`|폴더 만들기|`mkdir practice`|
|`touch`|파일 생성 또는 시간 정보 갱신|`touch memo.txt`|
|`cat`|텍스트 파일 내용 출력|`cat memo.txt`|
|`cp`|파일 복사|`cp memo.txt backup.txt`|
|`mv`|파일 이동 또는 이름 변경|`mv memo.txt notes.txt`|
|`rm`|파일 삭제|`rm notes.txt`|

`touch memo.txt`는 파일이 없으면 빈 파일을 만들고, 이미 있으면 일반적으로 파일의 시간 정보를 갱신한다.

**`rm`은 일반적으로 휴지통을 거치지 않고 삭제하므로**, 대상 경로를 확인하고 사용해야 한다.

### 명령어 앞의 `$`

설명 문서에서는 다음처럼 표시하기도 한다.

```
$ pwd
```

여기서 `$`는 입력을 기다리는 **프롬프트 표시**이다. 보통 실제로 입력할 부분은 `pwd`뿐이다.

프롬프트는 환경에 따라 `%`, `>`, 또는 사용자 이름과 현재 경로가 포함된 형태로 나타날 수 있다.

## CLI를 이해하는 핵심: 현재 위치와 경로

CLI에서는 **현재 어느 폴더에서 작업 중인지**가 매우 중요하다. 이를 **현재 작업 디렉터리**라고 한다.

예를 들어 다음 명령어는 현재 위치에 `practice` 폴더를 만든다.

```
mkdir practice
```

같은 명령어라도 현재 위치가 바탕화면인지, 문서 폴더인지에 따라 폴더가 만들어지는 장소가 달라진다.

### 절대 경로

파일 시스템의 기준점부터 전체 위치를 나타낸다.

```
/Users/minsu/Documents/memo.txt
```

### 상대 경로

현재 작업 디렉터리를 기준으로 위치를 나타낸다.

```
Documents/memo.txt
```

자주 사용하는 경로 표기는 다음과 같다.

|표기|의미|
|---|---|
|`.`|현재 폴더|
|`..`|상위 폴더|
|`~`|사용자 홈 폴더|
|`/`|macOS·Linux 파일 시스템의 루트|

예를 들어 다음 명령어는 상위 폴더로 이동한다.

```
cd ..
```

경로에 공백이 있으면 따옴표로 감싸는 것이 좋다.

```
cd "My Documents"
```

## CLI가 강력한 이유: 연결과 자동화

### 명령어의 결과를 다른 명령어에 전달하기

**파이프 `|`**를 사용하면 앞 명령어의 출력을 뒤 명령어의 입력으로 전달할 수 있다.

```
cat app.log | grep "ERROR"
```

이 명령어는 다음 순서로 동작한다.

1. `cat`이 `app.log`의 내용을 출력한다.
2. `grep`이 그 내용에서 `ERROR`가 포함된 줄을 찾는다.

이 작업 자체는 다음처럼 더 간단하게 작성할 수도 있다.

```
grep "ERROR" app.log
```

파이프의 가치는 여러 도구를 연결해 더 복잡한 작업을 처리할 때 커진다.

### 반복 작업을 스크립트로 만들기

매번 같은 명령어를 입력한다면 파일에 저장해 반복 실행할 수 있다. 이렇게 명령어들을 묶은 파일을 **스크립트**라고 부른다.

예를 들어 다음 작업을 자동화할 수 있다.

- 매일 특정 폴더의 파일 백업하기
- 여러 파일의 이름을 일정한 규칙으로 바꾸기
- 소스 코드 검사와 테스트 실행하기
- 데이터를 내려받고 필요한 정보만 추출하기
- 애플리케이션을 빌드하고 배포하기

단, 정해진 시간에 자동으로 실행하려면 스크립트 외에 작업 스케줄러 같은 실행 장치도 필요하다.

## CLI 사용하는 곳

|분야|활용 예|
|---|---|
|소프트웨어 개발|개발 서버 실행, 패키지 설치, 테스트|
|버전 관리|Git으로 변경 기록 확인 및 관리|
|서버 운영|원격 서버 접속, 로그 확인, 서비스 관리|
|데이터 처리|텍스트 검색, 파일 변환, 데이터 집계|
|클라우드 관리|서버와 저장소 등 리소스 조회 및 설정|
|일상적인 파일 작업|대량 복사, 이름 변경, 정리|

예를 들어 다음 명령어들은 모두 CLI를 사용하는 방식이다.

```
git status
```

Git 저장소의 상태를 확인한다.

```
npm run dev
```

프로젝트에 정의된 `dev` 스크립트를 실행한다. 웹 프로젝트에서는 개발 서버를 시작하도록 설정하는 경우가 많다.

```
python script.py
```

Python으로 `script.py` 파일을 실행한다.

각 명령어를 사용하려면 해당 프로그램이 설치되어 있어야 하며, 일부 명령어는 적절한 프로젝트 폴더에서 실행해야 한다.

## 자주 막히는 부분

### “command not found”

셸이 입력한 이름의 명령어를 찾지 못했다는 뜻이다. 주로 다음 원인이 있다.

- 프로그램이 설치되지 않았다.
- 명령어 이름을 잘못 입력했다.
- 프로그램의 위치가 `PATH`에 등록되지 않았다.

**`PATH`는 셸이 실행할 프로그램을 찾을 때 확인하는 폴더 목록**이다.

### “No such file or directory”

지정한 파일이나 폴더를 찾을 수 없다는 뜻이다.

우선 `pwd`로 현재 위치를 확인하고, `ls`로 파일 이름이 맞는지 확인하면 도움이 된다.

### “Permission denied”

파일 접근이나 실행에 필요한 권한이 없다는 뜻이다. 파일의 소유권, 접근 권한, 실행 권한 등을 확인해야 한다.

### 명령어가 끝나지 않는다

개발 서버처럼 계속 실행되는 것이 정상인 프로그램도 있다. 일반적으로 **`Ctrl + C`**를 누르면 현재 실행 중인 프로그램에 중단을 요청할 수 있다.

## 배우는 순서

1. **현재 위치와 파일 목록 확인:** `pwd`, `ls`
2. **폴더 이동:** `cd`, 상대 경로, 절대 경로
3. **파일과 폴더 조작:** `mkdir`, `cp`, `mv`
4. **내용 확인과 검색:** `cat`, `grep`
5. **출력 연결과 저장:** `|`, `>`, `>>`
6. **자주 쓰는 작업 자동화:** 셸 스크립트
