## 퀵 정렬의 개념

**퀵 정렬(Quick Sort)은 기준값인 피벗을 선택하고, 피벗을 기준으로 데이터를 나눈 뒤 각 부분을 정렬하는 알고리즘이다.**

앞에서 살펴본 병합 정렬처럼 **분할 정복(Divide and Conquer)** 방식을 사용한다.

오름차순 퀵 정렬의 기본 흐름은 다음과 같다.

1. 리스트에서 기준이 될 원소인 피벗을 선택한다.
2. 피벗보다 작은 값과 큰 값을 서로 다른 구간으로 나눈다.
3. 나누어진 각 구간에 같은 과정을 반복한다.
4. 처리할 구간의 원소가 하나 이하가 되면 종료한다.

같은 값이 있을 때 어느 구간에 배치할지는 분할 방식에 따라 달라진다. 여기서는 **피벗 이하의 값은 왼쪽에, 피벗보다 큰 값은 오른쪽에 배치하는 방식**으로 설명한다.

```
[피벗 이하의 값들 | 피벗 | 피벗보다 큰 값들]
```

이 단계에서 왼쪽과 오른쪽 구간 내부까지 정렬되어 있을 필요는 없다. 각 구간을 다시 정렬하면 전체 정렬이 완성된다.

---

## 피벗과 분할

### 피벗은 데이터를 나누는 기준값

피벗은 현재 정렬할 구간에서 선택한 원소이다.

예를 들어 다음 리스트에서 `6`을 피벗으로 선택한 상황이다.

```
[5, 3, 8, 4, 2, 7, 1, 6]
                      ↑
                     피벗
```

피벗을 기준으로 분할하면 다음과 같은 상태를 만들 수 있다.

```
[5, 3, 4, 2, 1 | 6 | 8, 7]
```

왼쪽에는 `6` 이하인 값이 있고, 오른쪽에는 `6`보다 큰 값이 있다.

### 분할은 원소를 피벗 기준으로 재배치하는 작업

이처럼 원소들을 피벗 기준으로 나누는 작업을 **분할(partition)**이라고 한다.

퀵 정렬에는 여러 분할 방식이 있다. 이 설명에서는 **마지막 원소를 피벗으로 사용하는 로무토 분할(Lomuto partition)**을 사용한다.

이 방식은 분할이 끝나면 피벗의 최종 위치가 확정된다. 이후 재귀 호출에서는 해당 피벗을 제외한 왼쪽과 오른쪽 구간만 처리한다.

다른 분할 방식에서는 피벗 위치와 재귀 범위의 의미가 달라질 수 있으므로, 분할 코드와 재귀 범위는 함께 이해해야 한다.

## 분할 과정

다음 리스트를 오름차순으로 정렬하는 상황이다.

```
[5, 3, 8, 4, 2, 7, 1, 6]
```

마지막 원소인 `6`을 피벗으로 선택한다.

분할 과정에서는 두 인덱스를 사용한다.

- `j`는 현재 확인하는 원소의 위치이다.
- `i`는 피벗 이하인 원소를 다음에 넣을 위치이다.

처음에는 `i`와 `j`가 모두 인덱스 `0`에서 시작한다.

### 첫 번째 단계: 5와 3을 확인한다

`5`와 `3`은 모두 피벗 `6` 이하이다. 이미 왼쪽에 있으므로 위치를 유지하며 `i`를 증가시킨다.

```
[5, 3 | 8, 4, 2, 7, 1 | 6]
       ↑
       i
```

이제 인덱스 `2`가 다음 작은 값을 넣을 위치이다.

### 두 번째 단계: 8을 확인한다

`8`은 피벗보다 크므로 그대로 두고 다음 원소를 확인한다.

이때 `i`는 이동하지 않는다.

### 세 번째 단계: 4를 확인한다

`4`는 피벗 이하이므로 `i`가 가리키는 `8`과 교환한다.

```
[5, 3, 8, 4, 2, 7, 1, 6]
          ↓
[5, 3, 4, 8, 2, 7, 1, 6]
```

작은 값을 왼쪽에 추가했으므로 `i`를 한 칸 증가시킨다.

### 네 번째 단계: 2를 확인한다

`2`도 피벗 이하이므로 현재 `i`가 가리키는 `8`과 교환한다.

```
[5, 3, 4, 8, 2, 7, 1, 6]
          ↓
[5, 3, 4, 2, 8, 7, 1, 6]
```

다시 `i`를 한 칸 증가시킨다.

### 다섯 번째 단계: 7과 1을 확인한다

`7`은 피벗보다 크므로 그대로 둔다.

이후 `1`을 확인하면 피벗 이하이므로 `i`가 가리키는 `8`과 교환한다.

```
[5, 3, 4, 2, 8, 7, 1, 6]
          ↓
[5, 3, 4, 2, 1, 7, 8, 6]
```

이제 피벗을 제외한 모든 원소를 확인한 상태이다.

### 여섯 번째 단계: 피벗을 배치한다

현재 `i`는 피벗보다 큰 구간의 첫 번째 위치를 가리킨다.

해당 위치의 `7`과 마지막에 있는 피벗 `6`을 교환한다.

```
[5, 3, 4, 2, 1, 7, 8, 6]
          ↓
[5, 3, 4, 2, 1 | 6 | 8, 7]
```

피벗 `6`의 최종 위치가 확정된다.

이후 왼쪽과 오른쪽 구간을 각각 퀵 정렬로 처리한다.

```
왼쪽 구간: [5, 3, 4, 2, 1] → [1, 2, 3, 4, 5]

오른쪽 구간: [8, 7] → [7, 8]
```

최종 결과는 다음과 같다.

```
[1, 2, 3, 4, 5, 6, 7, 8]
```

## 예제 코드

다음 코드는 마지막 원소를 피벗으로 사용하고, 원본 리스트 안에서 원소를 교환하는 구현이다.

```
def partition(numbers: list[int], low: int, high: int) -> int:
    """구간을 피벗 기준으로 분할하고 피벗의 위치를 반환한다."""
    pivot = numbers[high]
    i = low

    for j in range(low, high):
        if numbers[j] <= pivot:
            numbers[i], numbers[j] = numbers[j], numbers[i]
            i += 1

    # 피벗을 두 구간 사이에 배치한다.
    numbers[i], numbers[high] = numbers[high], numbers[i]

    return i


def quick_sort(numbers: list[int]) -> None:
    """전달받은 리스트를 퀵 정렬로 오름차순 정렬한다."""

    def sort_range(low: int, high: int) -> None:
        # 원소가 하나 이하인 구간은 정렬할 필요가 없다.
        if low >= high:
            return

        pivot_index = partition(numbers, low, high)

        # 최종 위치가 확정된 피벗을 제외하고 정렬한다.
        sort_range(low, pivot_index - 1)
        sort_range(pivot_index + 1, high)

    sort_range(0, len(numbers) - 1)


numbers = [5, 3, 8, 4, 2, 7, 1, 6]

print("정렬 전:", numbers)
quick_sort(numbers)
print("정렬 후:", numbers)
```

실행 결과는 다음과 같다.

```
정렬 전: [5, 3, 8, 4, 2, 7, 1, 6]
정렬 후: [1, 2, 3, 4, 5, 6, 7, 8]
```

**이 함수는 원본 리스트를 직접 수정하며, 반환값은 `None`이다.**

빈 리스트나 원소가 하나인 리스트는 종료 조건에 바로 도달하므로 그대로 유지된다.

## 코드의 세부 동작

### 정렬 범위를 인덱스로 전달한다

```
sort_range(low, high)
```

`low`와 `high`는 정렬할 구간의 시작과 끝 인덱스이다. 양 끝 원소를 모두 포함한다.

예를 들어 다음 호출은 인덱스 `2`부터 `5`까지 정렬한다는 의미이다.

```
sort_range(2, 5)
```

리스트를 슬라이싱하여 새로 만들지 않고, 같은 리스트의 일부 구간을 처리한다.

### 마지막 원소를 피벗으로 선택한다

```
pivot = numbers[high]
```

현재 구간의 마지막 원소를 기준값으로 사용한다.

이 선택은 구현을 단순하게 만들지만, 입력 순서에 따라 분할이 치우칠 수 있다.

### i는 작은 값이 들어갈 경계이다

```
i = low
```

분할 반복문에서 현재 원소를 처리하기 직전에는 다음 상태를 유지한다.

```
numbers[low:i]  → 피벗 이하인 원소들의 구간이다.
numbers[i:j]   → 피벗보다 큰 원소들의 구간이다.
numbers[j:high] → 아직 확인하지 않은 구간이다.
numbers[high]  → 피벗이다.
```

현재 값이 피벗 이하라면 `numbers[i]`와 교환하고 `i`를 증가시킨다.

```
if numbers[j] <= pivot:
    numbers[i], numbers[j] = numbers[j], numbers[i]
    i += 1
```

이렇게 하면 피벗 이하인 구간을 왼쪽부터 확장할 수 있다.

### 피벗은 반복문에서 제외한다

```
for j in range(low, high):
```

`range()`의 끝값인 `high`는 포함되지 않는다.

피벗은 마지막에 따로 배치해야 하므로, 반복문에서는 피벗 직전 원소까지만 확인한다.

### 재귀 범위에서 피벗을 제외한다

```
sort_range(low, pivot_index - 1)
sort_range(pivot_index + 1, high)
```

분할이 끝난 피벗은 이미 최종 위치에 있다.

따라서 다시 정렬할 필요가 없으며, 왼쪽과 오른쪽 구간에서 제외한다. 각 재귀 호출의 구간이 줄어들기 때문에 종료 조건에 도달할 수 있다.

## 시간 복잡도

### 분할 한 번의 시간 복잡도는 O(n)이다

현재 구간에 원소가 `n`개라면 피벗을 제외한 `n - 1`개 원소를 확인한다.

각 원소에 대해 비교와 필요한 교환을 수행하므로 분할 한 번의 시간 복잡도는 `O(n)`이다.

전체 실행 시간은 이러한 분할이 얼마나 균형 있게 이루어지는지에 따라 달라진다.

### 최선의 경우: O(n log n)이다

피벗이 매번 구간을 비슷한 크기로 나누면 재귀 깊이가 `O(log n)`이 된다.

```
               n
          /         \
        n/2         n/2
       /   \       /   \
     n/4   n/4   n/4   n/4
```

각 깊이에서 처리하는 구간들의 전체 크기는 `O(n)`이다.

따라서 전체 시간 복잡도는 다음과 같다.

```
깊이당 처리량 O(n) × 재귀 깊이 O(log n)
= O(n log n)
```

### 평균적인 경우: O(n log n)이다

서로 다른 값들이 무작위 순서로 주어지는 일반적인 평균 분석에서는 시간 복잡도가 `O(n log n)`이다.

매번 정확히 반으로 나눌 필요는 없다. 분할이 지속적으로 한쪽에 극단적으로 치우치지 않으면 효율적인 정렬을 수행한다.

### 최악의 경우: O(n²)이다

피벗이 매번 최솟값이나 최댓값이면 한쪽 구간은 비고, 다른 쪽에는 원소가 거의 모두 남는다.

```
n → n - 1 → n - 2 → ... → 1
```

원소 비교 횟수는 다음과 같이 누적된다.

```
(n - 1) + (n - 2) + ... + 1
= n(n - 1) / 2
```

따라서 최악의 시간 복잡도는 `O(n²)`이다.

|상황|시간 복잡도|분할 상태|
|---|---|---|
|최선|`O(n log n)`이다.|각 구간이 비슷한 크기로 나뉜다.|
|평균|`O(n log n)`이다.|평균적으로 분할이 충분히 균형을 이룬다.|
|최악|`O(n²)`이다.|원소가 거의 모두 한쪽 구간에 남는다.|

## 피벗 선택과 중복값의 영향

### 마지막 원소를 피벗으로 선택하는 경우

앞의 코드에 이미 정렬된 리스트를 넣는 상황이다.

```
[1, 2, 3, 4, 5]
```

첫 피벗은 `5`이므로 나머지 모든 값이 왼쪽에 놓인다.

```
[1, 2, 3, 4 | 5]
```

다음 피벗은 `4`이며 같은 상황이 반복된다.

```
[1, 2, 3 | 4]
```

따라서 이 구현에서는 이미 정렬된 입력도 최악의 경우가 된다. 역순 입력에서도 분할이 극단적으로 치우칠 수 있다.

### 무작위 피벗을 선택하는 경우

현재 구간에서 원소 하나를 무작위로 선택하여 피벗으로 사용할 수 있다.

앞의 분할 함수를 유지하려면 선택한 원소를 마지막 위치로 옮긴 뒤 분할하면 된다.

서로 다른 값으로 이루어진 입력에서는 무작위 피벗을 사용하여 입력 순서와 관계없이 기대 시간 복잡도 `O(n log n)`을 얻을 수 있다. 다만 최악의 시간 복잡도 자체가 사라지는 것은 아니다.

### 세 값의 중앙값을 사용하는 경우

첫 번째, 가운데, 마지막 원소의 값 중 중앙값을 피벗으로 선택하는 방법도 있다.

이는 일부 입력에서 극단적인 피벗 선택을 줄이는 데 도움이 된다. 다만 이 방법도 최악의 경우를 완전히 제거하지는 않는다.

### 중복값이 많은 경우

앞의 코드는 피벗과 같은 값도 모두 왼쪽에 배치한다.

다음처럼 모든 값이 같다면 매번 한쪽에 원소가 몰린다.

```
[3, 3, 3, 3, 3]
```

따라서 이 경우에도 시간 복잡도가 `O(n²)`이 된다.

**모든 값이 같은 입력은 피벗을 무작위로 선택해도 이 분할 방식의 문제가 해결되지 않는다.**

중복값이 많을 때는 다음과 같이 세 구간으로 나누는 **3방향 분할**을 사용할 수 있다.

```
[피벗보다 작은 값 | 피벗과 같은 값 | 피벗보다 큰 값]
```

가운데의 같은 값들은 추가 정렬에서 제외하고, 양쪽 구간만 재귀적으로 처리한다.

## 공간 복잡도와 재귀 깊이

### 분할 자체의 추가 공간은 O(1)이다

앞의 분할 함수는 원본 리스트에서 원소를 교환하며, 피벗과 인덱스 등의 변수만 사용한다.

따라서 분할 자체의 추가 공간 복잡도는 `O(1)`이다.

### 재귀 호출 공간은 별도로 필요하다

앞의 구현은 재귀 호출을 사용하므로 호출 스택이 필요하다.

|분할 상태|재귀 깊이|전체 추가 공간|
|---|---|---|
|균형 잡힌 분할|`O(log n)`이다.|`O(log n)`이다.|
|일반적인 평균 분석|평균 `O(log n)`이다.|평균 `O(log n)`이다.|
|극단적으로 치우친 분할|`O(n)`이다.|`O(n)`이다.|

퀵 정렬은 원본 배열 안에서 분할하므로 제자리 정렬로 분류하는 경우가 많다. 다만 **앞의 재귀 구현에서 전체 추가 공간까지 항상 `O(1)`이라고 설명하면 정확하지 않다.**

Python에서는 재귀 깊이에 제한이 있으므로, 큰 입력에서 분할이 심하게 치우치면 `RecursionError`가 발생할 수 있다.

작은 쪽 구간만 재귀 호출하고 큰 쪽은 반복문으로 처리하면 호출 스택을 `O(log n)`으로 제한할 수 있다. 이 개선은 스택 사용량을 줄이지만, 나쁜 분할로 발생하는 `O(n²)`의 실행 시간까지 해결하지는 않는다.

---

## 퀵 정렬의 안정성

**안정 정렬(stable sort)은 정렬 기준값이 같은 원소들의 기존 상대적 순서를 유지하는 정렬이다.**

일반적인 원소 교환 방식의 퀵 정렬은 안정 정렬이 아니다.

같은 값 `2`를 구분하기 위해 `A`, `B`를 붙인 상황이다. 비교는 숫자만 기준으로 한다.

```
[2A, 2B, 1]
```

마지막 값인 `1`을 피벗으로 선택한다.

`2A`와 `2B`는 모두 피벗보다 크므로 탐색 중에는 이동하지 않는다. 마지막에 피벗 `1`과 첫 번째 원소 `2A`를 교환한다.

```
[2A, 2B, 1]
      ↓
[1, 2B, 2A]
```

같은 값의 순서가 `2A → 2B`에서 `2B → 2A`로 뒤집힌다.

따라서 앞의 구현은 **불안정 정렬**이다. 안정성을 유지하는 변형도 가능하지만, 별도의 저장 공간이나 다른 분할 설계가 필요할 수 있다.

---

## 병합 정렬과의 차이

두 알고리즘은 모두 분할 정복을 사용하지만, 실제로 원소를 정리하는 시점이 다르다.

**퀵 정렬은 피벗을 기준으로 원소를 재배치한 뒤 각 구간을 정렬한다.**

**병합 정렬은 각 구간을 먼저 정렬한 뒤, 두 정렬 결과를 병합한다.**

|비교 항목|퀵 정렬|병합 정렬|
|---|---|---|
|구간을 나누는 기준|피벗과의 값 비교로 나눈다.|인덱스의 가운데를 기준으로 나눈다.|
|주요 작업|재귀 호출 전에 분할을 수행한다.|재귀 호출 후에 병합을 수행한다.|
|평균 시간 복잡도|`O(n log n)`이다.|`O(n log n)`이다.|
|최악 시간 복잡도|`O(n²)`이다.|`O(n log n)`이다.|
|추가 공간|앞의 구현은 평균 `O(log n)`, 최악 `O(n)`이다.|앞서 설명한 리스트 기반 구현은 `O(n)`이다.|
|안정성|일반적인 교환 방식은 불안정 정렬이다.|같은 값에서 왼쪽을 먼저 선택하면 안정 정렬이다.|

퀵 정렬은 분할 후 피벗 양쪽의 순서 관계가 이미 정해져 있으므로, 각 부분을 정렬한 뒤 별도의 병합 작업이 필요하지 않다.

## 내림차순 정렬로 변경하는 방법

내림차순으로 정렬하려면 분할 함수의 비교 조건을 다음과 같이 바꾸면 된다.

```
if numbers[j] >= pivot:
```

이 조건을 사용하면 왼쪽에는 피벗 이상의 값이, 오른쪽에는 피벗보다 작은 값이 놓인다.

```
[피벗 이상의 값들 | 피벗 | 피벗보다 작은 값들]
```

피벗의 최종 배치와 양쪽 구간의 재귀 호출 방식은 동일하다.

예제 입력의 최종 결과는 다음과 같다.

```
[8, 7, 6, 5, 4, 3, 2, 1]
```

## 장점과 한계

### 장점

- 평균적으로 `O(n log n)`에 정렬한다.
- 원본 리스트 안에서 분할하므로 병합용 결과 리스트가 필요하지 않다.
- 피벗의 위치가 확정되면 해당 원소를 이후 처리에서 제외한다.
- 각 구간의 정렬이 끝나면 별도의 병합 없이 전체 정렬이 완성된다.

### 한계

- 분할이 치우치면 시간 복잡도가 `O(n²)`으로 악화된다.
- 피벗 선택과 중복값 처리 방식이 성능에 큰 영향을 준다.
- 일반적인 교환 방식은 안정 정렬이 아니다.
- 단순한 재귀 구현은 나쁜 분할에서 호출 스택이 깊어질 수 있다.

실제 Python 프로그램에서 일반적인 정렬 작업을 수행할 때는 내장 기능을 사용하는 것이 보통 더 적합하다.

```
numbers = [5, 3, 8, 4, 2, 7, 1, 6]

# 원본을 유지하면서 정렬된 새 리스트를 만든다.
sorted_numbers = sorted(numbers)

# 기존 리스트를 직접 정렬한다.
numbers.sort()
```
