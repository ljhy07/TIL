## 선택 정렬의 개념

**선택 정렬(Selection Sort)은 정렬되지 않은 구간에서 가장 작은 원소를 찾아, 해당 구간의 맨 앞 원소와 교환하는 정렬 알고리즘이다.**

오름차순 정렬에서는 작은 값부터 하나씩 선택하여 왼쪽부터 배치한다. 내림차순 정렬에서는 큰 값부터 선택하여 배치한다.

예를 들어 다음 리스트를 오름차순으로 정렬한다고 가정한다.

```
[5, 3, 4, 1, 2]
```

전체에서 가장 작은 값인 `1`을 찾아 첫 번째 원소인 `5`와 교환한다.

```
[1, 3, 4, 5, 2]
```

이제 첫 번째 위치는 확정되므로, 나머지 구간인 `[3, 4, 5, 2]`에서 가장 작은 값을 찾는다.

이 과정을 반복하면 전체 리스트가 정렬된다.

---

## 핵심 동작 원리

선택 정렬은 리스트를 다음 두 구간으로 나누어 처리한다.

```
[정렬이 완료된 구간 | 정렬되지 않은 구간]
```

처음에는 정렬이 완료된 구간이 비어 있다. 반복이 진행될 때마다 왼쪽의 정렬 완료 구간이 한 칸씩 늘어난다.

오름차순 선택 정렬의 처리 순서는 다음과 같다.

1. 정렬되지 않은 구간의 첫 번째 원소를 최솟값 후보로 지정한다.
2. 나머지 원소를 확인하며 더 작은 값이 있으면 최솟값 후보를 갱신한다.
3. 구간 전체를 확인한 뒤, 최솟값을 해당 구간의 첫 번째 원소와 교환한다.
4. 방금 배치한 원소를 정렬 완료 구간에 포함한다.
5. 정렬되지 않은 구간에 같은 과정을 반복한다.

**최솟값을 찾는 동안에는 위치만 기억하고, 탐색이 끝난 뒤에 교환한다는 점이 핵심이다.**

더 작은 값을 발견할 때마다 즉시 교환하는 방식은 여기서 설명하는 표준 선택 정렬과 동작이 다르다.

## 정렬 과정

다음 리스트를 오름차순으로 정렬하는 상황이다.

```
[5, 3, 4, 1, 2]
```

정렬되지 않은 구간에서 최솟값을 찾아 배치하는 한 차례의 과정을 **패스(pass)**라고 한다.

### 첫 번째 패스

전체 구간 `[5, 3, 4, 1, 2]`에서 최솟값을 찾는다.

|확인한 값|판단|현재 최솟값|
|---|---|---|
|5|첫 번째 값을 후보로 지정한다.|`5`|
|3|5보다 작으므로 후보를 갱신한다.|`3`|
|4|3보다 크므로 후보를 유지한다.|`3`|
|1|3보다 작으므로 후보를 갱신한다.|`1`|
|2|1보다 크므로 후보를 유지한다.|`1`|

탐색이 끝나면 최솟값인 `1`과 첫 번째 원소인 `5`를 교환한다.

```
[5, 3, 4, 1, 2]
         ↓
[1 | 3, 4, 5, 2]
```

전체에서 가장 작은 값인 `1`의 최종 위치가 확정된다.

### 두 번째 패스

정렬되지 않은 구간 `[3, 4, 5, 2]`에서 최솟값을 찾는다.

최솟값인 `2`와 해당 구간의 첫 번째 원소인 `3`을 교환한다.

```
[1 | 3, 4, 5, 2]
         ↓
[1, 2 | 4, 5, 3]
```

전체에서 두 번째로 작은 값인 `2`의 위치가 확정된다.

### 세 번째 패스

정렬되지 않은 구간 `[4, 5, 3]`에서 최솟값을 찾는다.

최솟값인 `3`과 해당 구간의 첫 번째 원소인 `4`를 교환한다.

```
[1, 2 | 4, 5, 3]
         ↓
[1, 2, 3 | 5, 4]
```

### 네 번째 패스

정렬되지 않은 구간 `[5, 4]`에서 최솟값을 찾는다.

최솟값인 `4`와 해당 구간의 첫 번째 원소인 `5`를 교환한다.

```
[1, 2, 3 | 5, 4]
         ↓
[1, 2, 3, 4 | 5]
```

남은 원소가 하나이므로 해당 원소의 위치도 자동으로 확정된다.

최종 결과는 다음과 같다.

```
[1, 2, 3, 4, 5]
```

## 예제 코드

다음 코드는 최솟값의 인덱스를 찾은 뒤, 필요한 경우에만 교환하는 선택 정렬이다.

```
def selection_sort(numbers: list[int]) -> None:
    """전달받은 리스트를 선택 정렬로 오름차순 정렬한다."""
    n = len(numbers)

    for i in range(n - 1):
        # 정렬되지 않은 구간의 첫 번째 원소를 후보로 지정한다.
        min_index = i

        # 나머지 구간에서 최솟값의 위치를 찾는다.
        for j in range(i + 1, n):
            if numbers[j] < numbers[min_index]:
                min_index = j

        # 최솟값이 현재 위치와 다를 때만 교환한다.
        if min_index != i:
            numbers[i], numbers[min_index] = (
                numbers[min_index],
                numbers[i],
            )


numbers = [5, 3, 4, 1, 2]

print("정렬 전:", numbers)
selection_sort(numbers)
print("정렬 후:", numbers)
```

실행 결과는 다음과 같다.

```
정렬 전: [5, 3, 4, 1, 2]
정렬 후: [1, 2, 3, 4, 5]
```

이 함수는 **전달받은 리스트 자체를 수정하며, 반환값은 `None`이다.**

따라서 다음과 같이 반환값을 다시 대입하면 `numbers`가 `None`이 된다.

```
numbers = [5, 3, 4, 1, 2]

# 함수의 반환값이 None이므로 numbers도 None이 된다.
numbers = selection_sort(numbers)
```

정렬된 리스트를 사용하려면 처음 예제처럼 함수를 호출한 뒤 기존 리스트를 사용해야 한다.

---

## 코드의 세부 동작

### 바깥쪽 반복문

```
for i in range(n - 1):
```

`i`는 이번 패스에서 최솟값을 배치할 위치이다.

각 패스 시작 시 구간의 의미는 다음과 같다.

```
numbers[:i]  → 정렬이 완료된 구간이다.
numbers[i:]  → 이번에 최솟값을 찾을 구간이다.
```

원소가 `n`개라면 `n - 1`개 원소의 위치만 확정하면 된다. 마지막 원소는 남은 자리에 자동으로 놓이므로 최대 `n - 1`번의 패스를 수행한다.

### 최솟값 후보 초기화

```
min_index = i
```

아직 다른 원소를 확인하지 않았으므로 정렬되지 않은 구간의 첫 번째 원소를 최솟값 후보로 지정한다.

값 자체가 아니라 **인덱스를 저장하는 이유는 탐색이 끝난 뒤 해당 위치의 원소를 교환해야 하기 때문이다.**

### 최솟값 탐색

```
for j in range(i + 1, n):
    if numbers[j] < numbers[min_index]:
        min_index = j
```

현재 후보 다음 원소부터 리스트 끝까지 확인한다.

더 작은 값이 발견되면 `min_index`를 갱신한다. 이 과정에서는 리스트의 원소를 이동시키지 않는다.

탐색이 끝나면 `min_index`는 정렬되지 않은 구간의 최솟값을 가리킨다.

### 원소 교환

```
if min_index != i:
    numbers[i], numbers[min_index] = (
        numbers[min_index],
        numbers[i],
    )
```

찾은 최솟값을 이번에 확정할 위치인 `i`에 배치한다.

최솟값이 이미 `i`에 있다면 교환을 생략한다. 따라서 한 패스에서 실제 교환은 최대 한 번만 발생한다.

## 시간 복잡도와 공간 복잡도

### 시간 복잡도

**선택 정렬은 입력이 이미 정렬되어 있어도 남은 구간 전체에서 최솟값을 찾아야 한다.**

따라서 최선, 평균, 최악의 시간 복잡도가 모두 `O(n²)`이다.

|상황|시간 복잡도|설명|
|---|---|---|
|최선|`O(n²)`|이미 정렬되어 있어도 모든 구간을 탐색한다.|
|평균|`O(n²)`|각 패스에서 남은 원소를 모두 비교한다.|
|최악|`O(n²)`|입력 순서와 관계없이 같은 수의 원소 비교를 수행한다.|

위 구현에서 원소 간 비교 횟수는 다음과 같다.

```
첫 번째 패스: n - 1번
두 번째 패스: n - 2번
세 번째 패스: n - 3번
...
마지막 패스: 1번
```

이를 합하면 다음과 같다.

```
(n - 1) + (n - 2) + ... + 1
= n(n - 1) / 2
```

예를 들어 원소가 5개라면 총 10번 비교한다.

```
4 + 3 + 2 + 1 = 10번
```

이 횟수는 이미 정렬된 입력에서도 동일하다.

### 교환 횟수

한 패스에서 최대 한 번만 교환하므로 전체 교환 횟수는 **최대 `n - 1`번**이다.

위 구현에서는 최솟값이 현재 위치에 있으면 교환을 생략하므로, 이미 정렬된 입력의 교환 횟수는 0번이다.

**비교 횟수는 `O(n²)`이지만 교환 횟수는 `O(n)`이라는 차이가 있다.**

### 공간 복잡도

입력 리스트 외에 `i`, `j`, `min_index` 등의 변수만 사용한다.

입력 크기에 비례하는 추가 리스트를 만들지 않으므로 추가 공간 복잡도는 `O(1)`이다.

이처럼 원본 리스트 안에서 원소를 재배치하므로 **제자리 정렬(in-place sort)**이다.

## 선택 정렬이 안정 정렬이 아닌 이유

**안정 정렬(stable sort)은 정렬 기준값이 같은 원소들의 기존 상대적 순서를 유지하는 정렬이다.**

일반적인 교환 방식의 선택 정렬은 안정 정렬이 아니다.

다음과 같이 같은 값 `2`를 구분하기 위해 `A`, `B`를 붙인 상황이다.

```
[2A, 2B, 1]
```

정렬 기준은 숫자이며, 처음에는 `2A`가 `2B`보다 앞에 있다.

첫 번째 패스에서 최솟값인 `1`을 찾아 첫 번째 원소인 `2A`와 교환한다.

```
[2A, 2B, 1]
      ↓
[1, 2B, 2A]
```

같은 값인 두 원소의 순서가 `2A → 2B`에서 `2B → 2A`로 바뀐다.

최솟값을 찾을 때 `<`를 사용하여 같은 값끼리 후보를 바꾸지 않아도, **멀리 떨어진 원소를 교환하는 과정에서 다른 원소의 순서가 뒤집힐 수 있다.**

선택한 최솟값을 꺼내고 중간 원소를 한 칸씩 뒤로 이동시키는 변형으로 안정성을 확보할 수 있지만, 앞에서 구현한 교환 방식에는 해당하지 않는다.

## 내림차순 정렬로 변경하는 방법

내림차순으로 정렬하려면 정렬되지 않은 구간에서 최댓값을 선택하면 된다.

```
def selection_sort_desc(numbers: list[int]) -> None:
    """전달받은 리스트를 선택 정렬로 내림차순 정렬한다."""
    n = len(numbers)

    for i in range(n - 1):
        max_index = i

        for j in range(i + 1, n):
            if numbers[j] > numbers[max_index]:
                max_index = j

        if max_index != i:
            numbers[i], numbers[max_index] = (
                numbers[max_index],
                numbers[i],
            )


numbers = [5, 3, 4, 1, 2]
selection_sort_desc(numbers)

print(numbers)
```

실행 결과는 다음과 같다.

```
[5, 4, 3, 2, 1]
```

오름차순에서는 최솟값을 왼쪽에 배치하고, 내림차순에서는 최댓값을 왼쪽에 배치한다.

## 버블 정렬과의 차이

앞에서 살펴본 버블 정렬과 선택 정렬은 모두 평균 시간 복잡도가 `O(n²)`이지만, 원소를 배치하는 방식이 다르다.

아래 비교는 왼쪽에서 오른쪽으로 순회하는 오름차순 버블 정렬과, 앞에서 구현한 선택 정렬을 기준으로 한다.

|비교 항목|선택 정렬|버블 정렬|
|---|---|---|
|기본 동작|남은 구간의 최솟값을 찾아 앞에 배치한다.|인접한 원소를 비교하고 필요하면 교환한다.|
|패스마다 확정되는 위치|왼쪽에 작은 값의 위치가 확정된다.|오른쪽에 큰 값의 위치가 확정된다.|
|최선의 시간 복잡도|`O(n²)`이다.|교환 여부로 조기 종료하면 `O(n)`이다.|
|평균·최악의 시간 복잡도|`O(n²)`이다.|`O(n²)`이다.|
|최대 교환 횟수|`n - 1`번이다.|`n(n - 1) / 2`번이다.|
|안정성|일반적인 교환 방식은 불안정 정렬이다.|같은 값끼리 교환하지 않으면 안정 정렬이다.|
|추가 공간 복잡도|`O(1)`이다.|`O(1)`이다.|

선택 정렬은 원소를 교환하는 횟수가 적다는 특징이 있다. 다만 교환이 적더라도 비교는 계속 수행하므로, 전체 실행 시간이 항상 버블 정렬보다 짧다고 단정할 수는 없다.

## 장점과 한계

### 장점

- 최솟값을 찾아 앞에 배치한다는 원리가 단순하여 이해하기 쉽다.
- 추가 공간 복잡도가 `O(1)`이므로 별도의 큰 저장 공간이 필요하지 않다.
- 전체 교환 횟수가 최대 `n - 1`번으로 제한된다.
- 입력 순서와 관계없이 원소 비교 횟수가 일정하여 동작을 분석하기 쉽다.

### 한계

- 데이터가 많아지면 `O(n²)`의 비교 비용이 크게 증가한다.
- 이미 정렬된 데이터에서도 비교 횟수가 줄어들지 않는다.
- 일반적인 교환 방식은 같은 값의 기존 순서를 보장하지 않는다.

선택 정렬은 정렬 알고리즘의 원리와 비교·교환 비용의 차이를 학습하기에 적합하다. 실제 Python 프로그램에서 일반적인 정렬 작업을 수행할 때는 내장 정렬 기능을 사용하는 것이 보통 더 적합하다.

```
numbers = [5, 3, 4, 1, 2]

# 원본 리스트를 직접 정렬한다.
numbers.sort()

# 원본 리스트를 유지하면서 정렬된 새 리스트를 만든다.
original = [5, 3, 4, 1, 2]
sorted_numbers = sorted(original)
```
