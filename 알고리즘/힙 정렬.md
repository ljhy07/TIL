## 힙 정렬의 개념

**힙 정렬(Heap Sort)은 힙이라는 자료구조를 이용하여 최댓값이나 최솟값을 반복해서 꺼내며 정렬하는 알고리즘이다.**

오름차순 정렬에서는 일반적으로 **최대 힙(Max Heap)**을 사용한다.

최대 힙은 가장 큰 원소를 빠르게 확인할 수 있는 구조이다. 힙 정렬은 이 최댓값을 리스트의 맨 뒤에 배치하고, 남은 원소들에서 같은 과정을 반복한다.

전체 흐름은 다음과 같다.

1. 입력 리스트를 최대 힙으로 만든다.
2. 최대 힙의 최댓값을 정렬되지 않은 구간의 마지막 원소와 교환한다.
3. 방금 배치한 최댓값을 힙에서 제외한다.
4. 남은 구간을 다시 최대 힙으로 복구한다.
5. 힙에 원소가 하나만 남을 때까지 반복한다.

**가장 큰 값을 오른쪽부터 하나씩 확정한다는 점이 핵심이다.**

---

## 힙 자료구조의 이해

### 힙은 완전 이진 트리를 바탕으로 한다

이진 트리는 각 노드가 최대 두 개의 자식을 갖는 트리이다.

**완전 이진 트리는 마지막 층을 제외한 모든 층이 채워져 있고, 마지막 층은 왼쪽부터 빈자리 없이 채워지는 이진 트리이다.**

다음은 완전 이진 트리의 예시이다.

```
        10
       /  \
      5    3
     / \
    4   1
```

힙은 이러한 형태에 부모와 자식 사이의 값 조건을 추가한 자료구조이다.

### 최대 힙

최대 힙에서는 모든 부모 노드의 값이 자식 노드의 값 이상이다.

```
부모의 값 >= 자식의 값
```

앞의 트리는 최대 힙이다.

```
        10
       /  \
      5    3
     / \
    4   1
```

`10`은 `5`, `3` 이상이고, `5`는 `4`, `1` 이상이다.

이 조건이 트리 전체에서 성립하므로 **루트에는 전체 최댓값이 위치한다.**

다만 힙은 부모와 자식 사이의 관계만 보장한다. 형제끼리의 순서나 전체 원소의 정렬 순서까지 보장하지는 않는다.

### 최소 힙

최소 힙에서는 모든 부모 노드의 값이 자식 노드의 값 이하이다.

```
부모의 값 <= 자식의 값
```

따라서 루트에는 전체 최솟값이 위치한다.

|종류|부모와 자식의 관계|루트의 값|
|---|---|---|
|최대 힙|부모가 자식 이상이다.|전체 최댓값이다.|
|최소 힙|부모가 자식 이하이다.|전체 최솟값이다.|

---

## 리스트로 힙을 표현하는 방법

힙 정렬에서는 별도의 트리 노드를 만들지 않고, 리스트의 인덱스로 트리를 표현할 수 있다.

다음 최대 힙을 리스트로 나타내면 다음과 같다.

```
        10
       /  \
      5    3
     / \
    4   1
```

```
인덱스:  0   1  2  3  4
리스트: [10, 5, 3, 4, 1]
```

트리를 위에서 아래로, 같은 층에서는 왼쪽에서 오른쪽으로 저장한 형태이다.

인덱스가 `i`인 노드의 부모와 자식 위치는 다음 공식으로 계산한다.

|관계|인덱스|
|---|---|
|왼쪽 자식|`2 * i + 1`이다.|
|오른쪽 자식|`2 * i + 2`이다.|
|부모|루트가 아닌 경우 `(i - 1) // 2`이다.|

예를 들어 인덱스 `1`에 있는 값 `5`의 자식 위치는 다음과 같다.

```
왼쪽 자식: 2 × 1 + 1 = 3
오른쪽 자식: 2 × 1 + 2 = 4
```

실제로 인덱스 `3`, `4`에는 각각 `4`, `1`이 있다.

자식 인덱스가 현재 힙의 크기 이상이면 해당 자식은 존재하지 않는다.

## 핵심 연산: 아래로 내려가며 힙 복구하기

힙 정렬에서는 부모와 자식의 관계가 깨졌을 때 이를 복구해야 한다.

여기서는 부모를 필요한 만큼 아래로 이동시키는 **내려보내기(sift down)** 연산을 사용한다.

최대 힙을 복구하는 순서는 다음과 같다.

1. 현재 노드의 자식 중 더 큰 값을 선택한다.
2. 현재 노드가 선택한 자식 이상이면 종료한다.
3. 현재 노드가 더 작으면 선택한 자식과 교환한다.
4. 교환 후 내려간 위치에서 같은 과정을 반복한다.

예를 들어 다음 상태에서 루트의 힙 조건이 깨진 상황이다.

```
         1
       /   \
      5     3
     /
    4
```

먼저 두 자식 중 더 큰 `5`와 `1`을 교환한다.

```
         5
       /   \
      1     3
     /
    4
```

내려간 `1`은 자식 `4`보다 작으므로 다시 교환한다.

```
         5
       /   \
      4     3
     /
    1
```

이제 최대 힙 조건을 만족한다.

**이 연산은 현재 노드의 왼쪽과 오른쪽 자식 부분 트리가 이미 힙이라는 전제에서 동작한다.** 힙을 처음 만들 때 아래쪽 노드부터 처리하는 이유도 이 전제를 만족시키기 위해서이다.

## 정렬 과정

다음 리스트를 오름차순으로 정렬하는 상황이다.

```
[4, 10, 3, 5, 1]
```

### 첫 번째 단계: 최대 힙을 만든다

입력을 트리로 표현하면 다음과 같다.

```
         4
       /   \
     10     3
     / \
    5   1
```

아래쪽의 부모부터 힙 조건을 확인한다.

`10`은 자식 `5`, `1` 이상이므로 그대로 둔다.

이후 루트 `4`를 처리한다. 더 큰 자식인 `10`과 교환하고, 내려간 `4`를 다시 자식 `5`와 교환한다.

최대 힙을 만든 결과는 다음과 같다.

```
        10
       /  \
      5    3
     / \
    4   1
```

```
[10, 5, 3, 4, 1]
```

### 두 번째 단계: 최댓값 10을 맨 뒤에 배치한다

루트 `10`과 마지막 원소 `1`을 교환한다.

```
[1, 5, 3, 4 | 10]
```

`10`의 최종 위치가 확정된다. 이후 힙 복구에서는 마지막의 `10`을 제외한다.

남은 구간을 최대 힙으로 복구한다.

```
[5, 4, 3, 1 | 10]
```

### 세 번째 단계: 최댓값 5를 배치한다

현재 힙의 루트 `5`와 힙의 마지막 원소 `1`을 교환한다.

```
[1, 4, 3 | 5, 10]
```

남은 구간을 복구한다.

```
[4, 1, 3 | 5, 10]
```

### 네 번째 단계: 최댓값 4를 배치한다

루트 `4`와 현재 힙의 마지막 원소 `3`을 교환한다.

```
[3, 1 | 4, 5, 10]
```

남은 `[3, 1]`은 이미 최대 힙이므로 추가 교환이 필요하지 않다.

### 다섯 번째 단계: 최댓값 3을 배치한다

루트 `3`과 현재 힙의 마지막 원소 `1`을 교환한다.

```
[1 | 3, 4, 5, 10]
```

남은 원소가 하나이므로 정렬이 완료된다.

전체 과정을 모으면 다음과 같다.

|단계|힙 복구까지 마친 상태|
|---|---|
|최대 힙 생성|`[10, 5, 3, 4, 1]`이다.|
|10의 위치 확정|`[5, 4, 3, 1 │ 10]`이다.|
|5의 위치 확정|`[4, 1, 3 │ 5, 10]`이다.|
|4의 위치 확정|`[3, 1 │ 4, 5, 10]`이다.|
|3의 위치 확정|`[1 │ 3, 4, 5, 10]`이다.|

## 예시 코드

다음 코드는 반복문으로 힙을 복구하며, 원본 리스트를 직접 정렬하는 구현이다.

```
def sift_down(numbers: list[int], heap_size: int, root: int) -> None:
    """자식 부분 트리가 최대 힙일 때 root부터 힙 조건을 복구한다."""
    while True:
        left = 2 * root + 1

        # 왼쪽 자식이 없으면 오른쪽 자식도 없으므로 종료한다.
        if left >= heap_size:
            return

        right = left + 1
        larger_child = left

        # 두 자식 중 더 큰 자식을 선택한다.
        if right < heap_size and numbers[right] > numbers[left]:
            larger_child = right

        # 부모가 더 큰 자식 이상이면 힙 조건을 만족한다.
        if numbers[root] >= numbers[larger_child]:
            return

        # 더 큰 자식을 올리고 현재 원소를 아래로 내린다.
        numbers[root], numbers[larger_child] = (
            numbers[larger_child],
            numbers[root],
        )

        root = larger_child


def heap_sort(numbers: list[int]) -> None:
    """전달받은 리스트를 힙 정렬로 오름차순 정렬한다."""
    n = len(numbers)

    # 마지막 부모부터 루트까지 최대 힙을 만든다.
    for root in range(n // 2 - 1, -1, -1):
        sift_down(numbers, n, root)

    # 최댓값을 오른쪽부터 배치한다.
    for end in range(n - 1, 0, -1):
        numbers[0], numbers[end] = numbers[end], numbers[0]

        # 위치가 확정된 원소를 제외하고 힙을 복구한다.
        sift_down(numbers, end, 0)


numbers = [4, 10, 3, 5, 1]

print("정렬 전:", numbers)
heap_sort(numbers)
print("정렬 후:", numbers)
```

실행 결과는 다음과 같다.

```
정렬 전: [4, 10, 3, 5, 1]
정렬 후: [1, 3, 4, 5, 10]
```

**이 함수는 원본 리스트를 수정하며, 반환값은 `None`이다.**

빈 리스트나 원소가 하나인 리스트에서는 두 반복문이 실행되지 않으므로 그대로 유지된다.

## 코드의 세부 동작

### 마지막 부모부터 힙을 만든다

```
for root in range(n // 2 - 1, -1, -1):
```

리스트로 표현한 완전 이진 트리에서 자식을 가진 마지막 노드의 인덱스는 `n // 2 - 1`이다.

그 뒤의 노드들은 모두 자식이 없는 리프 노드이다. 리프 하나는 그 자체로 힙 조건을 만족하므로 복구할 필요가 없다.

마지막 부모부터 루트 방향으로 처리하면, 현재 노드를 복구할 때 자식 부분 트리들은 이미 최대 힙인 상태이다.

### 힙의 크기는 리스트 길이와 달라질 수 있다

```
sift_down(numbers, heap_size, root)
```

`heap_size`는 현재 힙으로 사용하는 원소 개수이다.

예를 들어 다음 상태에서는 리스트 길이가 `5`이지만 힙의 크기는 `3`이다.

```
[4, 1, 3 | 5, 10]
```

마지막의 `5`, `10`은 정렬이 완료된 구간이므로 힙 복구에서 제외한다.

### 더 큰 자식과 교환한다

```
if right < heap_size and numbers[right] > numbers[left]:
    larger_child = right
```

최대 힙에서는 부모가 두 자식 모두 이상이어야 한다.

더 작은 자식과만 교환하면 다른 큰 자식이 부모보다 커서 힙 조건이 계속 깨질 수 있다. 따라서 두 자식 중 큰 자식을 선택한다.

### 힙 복구를 조기에 끝낼 수 있다

```
if numbers[root] >= numbers[larger_child]:
    return
```

부모가 더 큰 자식 이상이면 두 자식 모두 이상이다.

자식 부분 트리들은 이미 힙이므로 현재 위치에서 복구를 종료할 수 있다.

### end는 정렬할 마지막 위치이자 다음 힙의 크기이다

```
for end in range(n - 1, 0, -1):
    numbers[0], numbers[end] = numbers[end], numbers[0]
    sift_down(numbers, end, 0)
```

루트의 최댓값을 인덱스 `end`에 배치한 뒤에는 해당 원소를 힙에서 제외한다.

남은 힙은 인덱스 `0`부터 `end - 1`까지이므로 원소 개수는 `end`이다.

따라서 힙 복구 함수에 `end`를 힙의 크기로 전달한다.

## 시간 복잡도

### 힙 복구 한 번은 최대 O(log n)이다

힙은 완전 이진 트리이므로 높이가 `O(log n)`이다.

`sift_down()`은 한 번 교환할 때마다 한 층씩 내려간다. 따라서 최악의 경우 루트에서 리프까지 이동하며 `O(log n)`의 시간이 걸린다.

### 최대 힙을 처음 만드는 시간은 O(n)이다

힙 복구를 여러 노드에 적용하므로 처음에는 `O(n log n)`처럼 보일 수 있다. 하지만 아래쪽 노드들은 내려갈 수 있는 높이가 매우 작다.

- 리프 노드는 내려갈 필요가 없다.
- 리프 바로 위의 노드는 최대 한 층만 내려간다.
- 높은 위치의 노드는 여러 층 내려갈 수 있지만 그 개수가 적다.

노드 개수를 대략적으로 계산하면 전체 작업량은 다음 형태이다.

```
(n/4) × 1 + (n/8) × 2 + (n/16) × 3 + ...
```

이를 묶으면 다음과 같다.

```
n × (1/4 + 2/8 + 3/16 + ...)
```

괄호 안의 합이 일정한 값으로 수렴하므로, 아래쪽부터 힙을 만드는 전체 시간은 `O(n)`이다.

### 최댓값을 반복해서 배치하는 시간은 최악 O(n log n)이다

최댓값을 뒤로 배치하는 작업은 `n - 1`번 수행한다.

각 작업에서 힙 복구가 최대 `O(log n)`이므로 전체 정렬의 최악 시간 복잡도는 다음과 같다.

```
최대 힙 생성 + 반복적인 최댓값 배치
= O(n) + O(n log n)
= O(n log n)
```

일반적인 평균 분석에서도 전체 시간 복잡도는 `O(n log n)`이다.

### 위 구현의 특수한 최선의 경우

위 구현은 부모가 자식 이상이면 힙 복구를 즉시 종료한다.

따라서 다음처럼 **모든 값이 같은 입력에서는 전체 실행 시간이 `O(n)`이다.**

```
[3, 3, 3, 3, 3]
```

각 힙 복구가 상수 시간에 종료되고, 바깥 반복문들만 선형 횟수로 실행되기 때문이다.

|항목|시간 복잡도|
|---|---|
|아래쪽부터 최대 힙 생성|`O(n)`이다.|
|힙 복구 한 번의 최악 비용|`O(log n)`이다.|
|전체 정렬의 평균 비용|`O(n log n)`이다.|
|전체 정렬의 최악 비용|`O(n log n)`이다.|
|위 구현에서 모든 값이 같은 경우|`O(n)`이다.|

힙 정렬의 중요한 성능 보장은 **입력 순서와 관계없이 최악의 시간 복잡도가 `O(n log n)`이라는 점**이다.

## 공간 복잡도와 안정성

### 추가 공간 복잡도는 O(1)이다

위 구현은 원본 리스트 안에서 원소를 교환한다.

별도의 결과 리스트를 만들지 않으며, 힙 복구도 재귀 호출 대신 반복문으로 처리한다.

인덱스 등 일정한 수의 변수만 사용하므로 추가 공간 복잡도는 `O(1)`이다.

따라서 **제자리 정렬(in-place sort)**이다.

힙 복구를 재귀 함수로 작성하면 호출 스택이 필요하므로, 그 구현에서는 추가 공간을 따로 고려해야 한다.

### 일반적인 힙 정렬은 안정 정렬이 아니다

안정 정렬은 정렬 기준값이 같은 원소들의 기존 상대적 순서를 유지하는 정렬이다.

힙 정렬은 멀리 떨어진 원소를 교환하므로 같은 값의 순서가 뒤집힐 수 있다.

숫자만 비교하고, 같은 값 `2`를 `A`, `B`로 구분한 상황이다.

```
[2A, 2B, 1]
```

이 리스트는 이미 최대 힙 조건을 만족한다.

루트의 `2A`를 마지막 원소 `1`과 교환하면 다음과 같다.

```
[1, 2B | 2A]
```

남은 힙을 복구하고 마지막 교환까지 수행하면 다음 결과가 된다.

```
[1, 2B, 2A]
```

기존의 `2A → 2B` 순서가 `2B → 2A`로 바뀐다.

따라서 앞의 구현은 **불안정 정렬**이다.

## 내림차순 정렬로 변경하는 방법

원본 리스트의 오른쪽부터 정렬 위치를 확정하는 구조에서 내림차순 결과를 얻으려면 **최소 힙**을 사용한다.

최솟값을 오른쪽부터 배치하면 다음과 같이 정렬된다.

```
[10, 5, 4, 3, 1]
```

최소 힙을 복구하려면 앞의 `sift_down()`에서 두 비교 방향을 변경한다.

먼저 두 자식 중 더 작은 자식을 선택한다.

```
if right < heap_size and numbers[right] < numbers[left]:
    smaller_child = right
```

이후 부모가 더 작은 자식 이하라면 종료한다.

```
if numbers[root] <= numbers[smaller_child]:
    return
```

그 외에는 작은 자식과 교환하며 내려간다. 변수도 `larger_child` 대신 `smaller_child`로 일관되게 사용하면 된다.

**최대 힙에서 꺼낸 값을 오른쪽 끝에 배치하면 오름차순이고, 최소 힙에서 꺼낸 값을 오른쪽 끝에 배치하면 내림차순이다.**

## 선택 정렬·병합 정렬·퀵 정렬과의 비교

### 선택 정렬과의 관계

선택 정렬과 힙 정렬은 모두 남은 원소에서 최솟값이나 최댓값을 선택하여 위치를 확정한다.

선택 정렬은 매번 남은 구간 전체를 탐색한다.

힙 정렬은 최대 힙의 루트에서 최댓값을 바로 확인하고, 원소를 제거한 뒤 `O(log n)`에 힙을 복구한다.

이 구조를 사용하므로 반복적인 최댓값 선택 비용을 줄일 수 있다.

### 시간과 공간의 비교

아래 표는 앞에서 설명한 일반적인 구현을 기준으로 한다.

|알고리즘|평균 시간|최악 시간|추가 공간|안정성|
|---|---|---|---|---|
|선택 정렬|`O(n²)`이다.|`O(n²)`이다.|`O(1)`이다.|불안정 정렬이다.|
|병합 정렬|`O(n log n)`이다.|`O(n log n)`이다.|리스트 기반 구현은 `O(n)`이다.|안정 정렬이다.|
|퀵 정렬|`O(n log n)`이다.|`O(n²)`이다.|앞의 재귀 구현은 평균 `O(log n)`, 최악 `O(n)`이다.|불안정 정렬이다.|
|힙 정렬|`O(n log n)`이다.|`O(n log n)`이다.|위 반복문 구현은 `O(1)`이다.|불안정 정렬이다.|

힙 정렬은 최악의 시간 복잡도와 추가 공간 측면에서 강점이 있다.

다만 실제 실행 속도는 비교·교환 횟수와 메모리 접근 방식에도 영향을 받는다. 힙에서는 부모와 자식 사이를 이동하며 접근하므로, 인접한 원소를 순차적으로 처리하는 방식보다 캐시 활용이 불리할 수 있다.

따라서 시간 복잡도가 같더라도 항상 같은 실행 속도를 보장하는 것은 아니다.

## 장점과 한계

### 장점

- 최악의 경우에도 `O(n log n)`에 정렬한다.
- 반복문으로 구현하면 추가 공간을 `O(1)`로 제한할 수 있다.
- 원본 리스트 안에서 정렬을 완료한다.
- 퀵 정렬처럼 피벗 선택에 따라 성능이 크게 악화되는 문제가 없다.
- 최댓값이나 최솟값을 관리하는 힙 자료구조의 원리를 함께 학습할 수 있다.

### 한계

- 일반적인 구현은 안정 정렬이 아니다.
- 부모·자식 인덱스와 힙 크기를 함께 관리해야 하므로 단순 정렬보다 구현이 복잡하다.
- 입력이 이미 정렬되어 있다는 사실을 직접 활용하는 구조는 아니다.
- 실제 성능은 메모리 접근 패턴과 비교·교환 비용에도 영향을 받는다.
