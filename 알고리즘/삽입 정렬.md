## 삽입 정렬의 개념

**삽입 정렬(Insertion Sort)은 원소를 하나씩 꺼내어, 앞쪽의 정렬된 구간에서 알맞은 위치에 삽입하는 정렬 알고리즘이다.**

손에 든 카드의 순서를 정리하는 과정과 비슷하다. 새로운 카드를 받으면 기존 카드들과 비교하여 들어갈 위치를 찾고, 그 자리에 카드를 끼워 넣는다.

예를 들어 다음 리스트를 오름차순으로 정렬한다고 가정한다.

```
[5, 3, 4, 1, 2]
```

처음에는 첫 번째 원소인 `5`만 정렬된 구간으로 본다.

```
[5 | 3, 4, 1, 2]
```

다음 원소인 `3`을 꺼내 정렬된 구간 `[5]`에 삽입한다. `3`은 `5`보다 작으므로 `5`를 오른쪽으로 이동시키고, 그 앞에 `3`을 넣는다.

```
[3, 5 | 4, 1, 2]
```

이제 정렬된 구간은 `[3, 5]`이다. 같은 방식으로 나머지 원소를 차례대로 삽입하면 전체 리스트가 정렬된다.

---

## 핵심 동작 원리

삽입 정렬은 리스트를 다음 두 구간으로 나누어 처리한다.

```
[정렬된 구간 | 아직 처리하지 않은 구간]
```

각 반복에서는 아직 처리하지 않은 구간의 첫 번째 원소를 선택한다. 이 원소를 **삽입할 값인 `key`**라고 한다.

오름차순 삽입 정렬의 처리 순서는 다음과 같다.

1. 두 번째 원소부터 시작하여 현재 값을 `key`에 저장한다.
2. 정렬된 구간의 오른쪽 끝에서 왼쪽 방향으로 비교한다.
3. `key`보다 큰 원소를 만나면 해당 원소를 오른쪽으로 한 칸 이동시킨다.
4. `key` 이하인 원소를 만나거나 리스트의 왼쪽 끝을 지나면 이동을 멈춘다.
5. 확보한 위치에 `key`를 삽입한다.
6. 다음 원소에 같은 과정을 반복한다.

**삽입할 값보다 큰 원소들을 오른쪽으로 밀고, 그 자리에 값을 넣는 것이 핵심이다.**

이때 정렬된 구간은 그 안에서 순서가 맞다는 의미이다. 이후 더 작은 값이 들어오면 기존 원소가 다시 오른쪽으로 이동할 수 있으므로, 각 원소의 최종 위치가 확정되었다는 의미는 아니다.

## 정렬 과정

다음 리스트를 오름차순으로 정렬하는 상황이다.

```
[5, 3, 4, 1, 2]
```

첫 번째 원소 하나는 이미 정렬된 구간으로 간주한다.

```
[5 | 3, 4, 1, 2]
```

### 첫 번째 삽입: 3을 배치한다

삽입할 값인 `key`는 `3`이다.

정렬된 구간 `[5]`의 오른쪽부터 비교한다.

- `5`는 `3`보다 크므로 오른쪽으로 한 칸 이동한다.
- 더 비교할 원소가 없으므로 맨 앞에 `3`을 삽입한다.

결과는 다음과 같다.

```
[3, 5 | 4, 1, 2]
```

### 두 번째 삽입: 4를 배치한다

삽입할 값인 `key`는 `4`이다.

정렬된 구간 `[3, 5]`의 오른쪽부터 비교한다.

- `5`는 `4`보다 크므로 오른쪽으로 한 칸 이동한다.
- `3`은 `4`보다 작으므로 이동을 멈춘다.
- `3`의 바로 뒤에 `4`를 삽입한다.

결과는 다음과 같다.

```
[3, 4, 5 | 1, 2]
```

### 세 번째 삽입: 1을 배치한다

삽입할 값인 `key`는 `1`이다.

정렬된 구간 `[3, 4, 5]`의 오른쪽부터 비교한다.

- `5`는 `1`보다 크므로 오른쪽으로 이동한다.
- `4`도 `1`보다 크므로 오른쪽으로 이동한다.
- `3`도 `1`보다 크므로 오른쪽으로 이동한다.
- 맨 앞에 `1`을 삽입한다.

결과는 다음과 같다.

```
[1, 3, 4, 5 | 2]
```

### 네 번째 삽입: 2를 배치한다

삽입할 값인 `key`는 `2`이다.

정렬된 구간 `[1, 3, 4, 5]`의 오른쪽부터 비교한다.

- `5`, `4`, `3`은 `2`보다 크므로 각각 오른쪽으로 이동한다.
- `1`은 `2`보다 작으므로 이동을 멈춘다.
- `1`의 바로 뒤에 `2`를 삽입한다.

최종 결과는 다음과 같다.

```
[1, 2, 3, 4, 5]
```

전체 과정을 모으면 다음과 같다.

|단계|삽입할 값|처리 후 리스트|
|---|---|---|
|초기 상태|첫 원소만 정렬된 구간으로 간주한다.|`[5 │ 3, 4, 1, 2]`|
|첫 번째 삽입|`3`을 삽입한다.|`[3, 5 │ 4, 1, 2]`|
|두 번째 삽입|`4`를 삽입한다.|`[3, 4, 5 │ 1, 2]`|
|세 번째 삽입|`1`을 삽입한다.|`[1, 3, 4, 5 │ 2]`|
|네 번째 삽입|`2`를 삽입한다.|`[1, 2, 3, 4, 5]`|

## 예시 코드

다음 코드는 큰 원소를 오른쪽으로 이동시킨 뒤, 확보한 위치에 `key`를 삽입하는 구현이다.

```
def insertion_sort(numbers: list[int]) -> None:
    """전달받은 리스트를 삽입 정렬로 오름차순 정렬한다."""
    for i in range(1, len(numbers)):
        # 삽입할 값을 별도로 보관한다.
        key = numbers[i]

        # 정렬된 구간의 마지막 원소부터 비교한다.
        j = i - 1

        # key보다 큰 원소를 오른쪽으로 한 칸씩 이동한다.
        while j >= 0 and numbers[j] > key:
            numbers[j + 1] = numbers[j]
            j -= 1

        # 이동이 끝난 자리에 key를 삽입한다.
        numbers[j + 1] = key


numbers = [5, 3, 4, 1, 2]

print("정렬 전:", numbers)
insertion_sort(numbers)
print("정렬 후:", numbers)
```

실행 결과는 다음과 같다.

```
정렬 전: [5, 3, 4, 1, 2]
정렬 후: [1, 2, 3, 4, 5]
```

이 함수는 **전달받은 리스트 자체를 수정하며 반환값은 `None`이다.** 정렬 결과는 함수 호출 이후의 `numbers`에서 확인한다.

빈 리스트나 원소가 하나뿐인 리스트에서는 반복문이 실행되지 않으므로 그대로 유지된다.

## 코드의 세부 동작

### 두 번째 원소부터 시작하는 이유

```
for i in range(1, len(numbers)):
```

원소가 하나뿐인 구간은 이미 정렬되어 있다.

따라서 첫 번째 원소를 정렬된 구간으로 보고, 두 번째 원소인 인덱스 `1`부터 삽입을 시작한다.

각 반복이 시작될 때 구간의 의미는 다음과 같다.

```
numbers[:i]  → 이미 정렬된 구간이다.
numbers[i]   → 이번에 삽입할 값이다.
numbers[i+1:] → 이후에 처리할 구간이다.
```

### 삽입할 값을 따로 저장하는 이유

```
key = numbers[i]
```

큰 원소를 오른쪽으로 이동시키는 과정에서 `numbers[i]`의 값이 덮어써질 수 있다.

따라서 원래 삽입하려던 값을 잃지 않도록 `key`에 보관한다.

예를 들어 `[5, 3]`에서 `3`을 삽입하는 과정은 다음과 같다.

```
key에 3을 보관한다.

[5, 3]
   ↓ 5를 오른쪽으로 복사한다.
[5, 5]
   ↓ 보관한 3을 맨 앞에 넣는다.
[3, 5]
```

중간에 같은 값이 두 번 나타나는 것은 정상적인 처리 과정이다. 삽입할 원래 값은 `key`에 보관되어 있다.

### 오른쪽 끝부터 비교하는 이유

```
j = i - 1
```

정렬된 구간에서 `key`가 들어갈 위치를 확보하려면, 뒤쪽 원소부터 오른쪽으로 이동시켜야 한다.

앞쪽부터 이동시키면 아직 옮기지 않은 원소를 덮어쓸 수 있다.

### while 조건의 의미

```
while j >= 0 and numbers[j] > key:
```

두 조건이 모두 참일 때 원소를 이동한다.

- `j >= 0`은 비교 위치가 리스트의 유효한 왼쪽 범위 안에 있다는 조건이다.
- `numbers[j] > key`는 현재 원소를 `key` 뒤로 이동해야 한다는 조건이다.

Python의 `and`는 왼쪽 조건이 거짓이면 오른쪽 조건을 평가하지 않는다. 따라서 `j`가 `-1`이 되면 `numbers[j] > key`를 평가하지 않고 반복을 끝낸다.

이 순서는 Python에서 음수 인덱스가 리스트 뒤쪽 원소를 가리킨다는 점 때문에도 중요하다.

### j + 1에 삽입하는 이유

```
numbers[j + 1] = key
```

반복문이 끝나는 경우는 두 가지이다.

1. `numbers[j] <= key`인 원소를 발견한 경우이다.
2. 모든 앞쪽 원소를 이동하여 `j`가 `-1`이 된 경우이다.

첫 번째 경우에는 발견한 원소의 바로 뒤인 `j + 1`에 삽입한다.

두 번째 경우에는 `j + 1`이 `0`이므로 맨 앞에 삽입한다.

## 시간 복잡도와 공간 복잡도

### 최선의 경우: O(n)이다

이미 오름차순으로 정렬된 입력이 최선의 경우이다.

```
[1, 2, 3, 4, 5]
```

각 `key`는 바로 앞 원소보다 크므로 이동할 필요가 없다. 각 삽입 단계에서 바로 앞 원소와 한 번 비교하고 다음 단계로 넘어간다.

원소가 `n`개라면 원소 간 비교는 `n - 1`번이므로 시간 복잡도는 `O(n)`이다.

### 최악의 경우: O(n²)이다

오름차순 정렬에서 입력이 내림차순이면 최악의 경우이다.

```
[5, 4, 3, 2, 1]
```

각 `key`가 정렬된 구간의 모든 원소보다 작으므로, 앞쪽 원소를 모두 오른쪽으로 이동해야 한다.

단계별 이동 횟수는 다음과 같다.

```
두 번째 원소 삽입: 1번
세 번째 원소 삽입: 2번
네 번째 원소 삽입: 3번
...
마지막 원소 삽입: n - 1번
```

전체 이동 횟수는 다음과 같다.

```
1 + 2 + 3 + ... + (n - 1)
= n(n - 1) / 2
```

따라서 최악의 시간 복잡도는 `O(n²)`이다.

### 평균적인 경우: O(n²)이다

서로 다른 값이 무작위 순서로 주어지는 일반적인 평균 분석에서는, 각 원소가 앞쪽 원소의 일부를 밀어내야 한다.

전체 비교와 이동 횟수가 `n²`에 비례하므로 평균 시간 복잡도는 `O(n²)`이다.

|상황|시간 복잡도|설명|
|---|---|---|
|최선|`O(n)`|이미 정렬되어 있어 원소 이동이 필요하지 않다.|
|평균|`O(n²)`|여러 원소를 비교하고 이동한다.|
|최악|`O(n²)`|각 삽입에서 앞쪽 원소를 모두 이동한다.|

### 공간 복잡도: O(1)이다

입력 리스트 외에 `key`, `i`, `j` 등의 변수만 사용한다.

입력 크기에 비례하는 추가 저장 공간을 만들지 않으므로 추가 공간 복잡도는 `O(1)`이다.

따라서 위 구현은 **제자리 정렬(in-place sort)**이다.

## 거의 정렬된 데이터에서 효율적인 이유

삽입 정렬은 각 원소가 들어갈 위치가 현재 위치와 가까우면 적은 이동으로 정렬을 진행한다.

예를 들어 다음 리스트는 `4`와 `5`의 순서만 바뀐 상태이다.

```
[1, 2, 3, 5, 4, 6]
```

대부분의 원소는 바로 앞 원소와 비교한 뒤 이동 없이 넘어간다. `4`를 처리할 때만 `5`를 오른쪽으로 한 칸 이동한다.

이 특징은 **역전 쌍(inversion)**으로 설명할 수 있다.

역전 쌍은 앞에 있는 값이 뒤에 있는 값보다 큰 원소 쌍이다.

```
[3, 1, 2]
```

이 리스트에는 다음 두 역전 쌍이 있다.

```
(3, 1)
(3, 2)
```

앞에서 구현한 삽입 정렬의 오른쪽 이동 횟수는 역전 쌍의 개수와 같다. 역전 쌍의 개수를 `I`라고 하면 실행 시간은 더 세밀하게 `O(n + I)`로 표현할 수 있다.

따라서 **역전 쌍이 적은 입력에서는 삽입 정렬이 선형 시간에 가까운 성능을 보인다.**

## 삽입 정렬의 안정성

**안정 정렬(stable sort)은 정렬 기준값이 같은 원소들의 기존 상대적 순서를 유지하는 정렬이다.**

앞에서 구현한 삽입 정렬은 안정 정렬이다.

예를 들어 같은 값 `2`를 구분하기 위해 `A`, `B`를 붙인 상황이다.

```
[2A, 1, 2B]
```

숫자만 기준으로 정렬하면 결과는 다음과 같다.

```
[1, 2A, 2B]
```

`2B`를 삽입할 때 앞에 있는 `2A`는 값이 같으므로 이동하지 않는다. 따라서 원래 앞에 있던 `2A`가 계속 앞에 남는다.

안정성을 유지하는 핵심은 다음 비교 조건이다.

```
numbers[j] > key
```

이 조건을 다음과 같이 바꾸면 같은 값도 오른쪽으로 이동한다.

```
numbers[j] >= key
```

그 결과 뒤에 있던 같은 값이 앞쪽으로 들어갈 수 있으므로 안정성이 깨질 수 있다.

## 내림차순 정렬로 변경하는 방법

내림차순으로 정렬하려면 `key`보다 작은 원소를 오른쪽으로 이동시키면 된다.

비교 조건을 다음과 같이 변경한다.

```
while j >= 0 and numbers[j] < key:
```

전체 구현은 다음과 같다.

```
def insertion_sort_desc(numbers: list[int]) -> None:
    """전달받은 리스트를 삽입 정렬로 내림차순 정렬한다."""
    for i in range(1, len(numbers)):
        key = numbers[i]
        j = i - 1

        while j >= 0 and numbers[j] < key:
            numbers[j + 1] = numbers[j]
            j -= 1

        numbers[j + 1] = key


numbers = [5, 3, 4, 1, 2]
insertion_sort_desc(numbers)

print(numbers)
```

실행 결과는 다음과 같다.

```
[5, 4, 3, 2, 1]
```

## 버블 정렬·선택 정렬과의 비교

아래 비교는 앞에서 설명한 기본 구현들을 기준으로 하며, 버블 정렬에는 교환 여부에 따른 조기 종료를 적용한 상태이다.

|비교 항목|삽입 정렬|선택 정렬|버블 정렬|
|---|---|---|---|
|기본 동작|정렬된 구간에 현재 값을 삽입한다.|남은 구간의 최솟값을 앞에 배치한다.|인접한 원소를 비교하고 교환한다.|
|최선의 시간 복잡도|`O(n)`이다.|`O(n²)`이다.|`O(n)`이다.|
|평균 시간 복잡도|`O(n²)`이다.|`O(n²)`이다.|`O(n²)`이다.|

## 장점과 한계

### 장점

- 카드 정리와 비슷한 원리이므로 동작을 이해하기 쉽다.
- 추가 공간 복잡도가 `O(1)`이다.
- 같은 값의 기존 순서를 유지하는 안정 정렬이다.
- 이미 정렬된 입력은 `O(n)`에 처리한다.
- 거의 정렬된 입력에서는 원소 이동이 적다.
- 정렬된 데이터 뒤에 새 원소가 추가되면, 새 원소를 삽입하는 방식으로 정렬 상태를 유지할 수 있다.

### 한계

- 무작위 입력이나 역순 입력에서는 `O(n²)`의 시간이 필요하다.
- 작은 값이 뒤쪽에 있으면 앞쪽의 여러 원소를 이동해야 한다.
- 데이터가 많고 역전 쌍이 많을수록 이동 비용이 커진다.

실제 Python 프로그램에서 일반적인 정렬 작업을 수행할 때는 내장 정렬 기능을 사용하는 것이 보통 더 적합하다.

```
numbers = [5, 3, 4, 1, 2]

# 기존 리스트를 직접 정렬한다.
numbers.sort()

# 원본을 유지하면서 정렬된 새 리스트를 만든다.
original = [5, 3, 4, 1, 2]
sorted_numbers = sorted(original)
```
