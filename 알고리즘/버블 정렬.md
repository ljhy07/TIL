## 버블 정렬의 개념

**버블 정렬(Bubble Sort)은 서로 인접한 두 원소를 비교하고, 정렬 순서에 맞지 않으면 두 원소의 위치를 바꾸는 정렬 알고리즘이다.**

이 과정을 반복하면 전체 데이터가 정렬된다.

오름차순 정렬에서는 왼쪽 원소가 오른쪽 원소보다 클 때 두 원소를 교환한다. 왼쪽부터 오른쪽으로 비교하면 큰 값이 점차 오른쪽으로 이동한다.

이러한 움직임이 물속의 거품이 위로 올라가는 모습과 비슷하여 버블 정렬이라는 이름이 붙었다.

---

## 핵심 동작 원리

오름차순 버블 정렬은 다음 순서로 동작한다.

1. 첫 번째 원소와 두 번째 원소를 비교한다.
2. 왼쪽 원소가 더 크면 두 원소를 교환한다.
3. 비교 위치를 한 칸 옮겨 두 번째 원소와 세 번째 원소를 비교한다.
4. 정렬되지 않은 구간의 끝까지 이 과정을 반복한다.
5. 한 차례 순회가 끝나면 해당 구간의 최댓값이 맨 오른쪽에 놓인다.
6. 위치가 확정된 마지막 원소를 제외하고 다시 순회한다.

여기서 **정렬되지 않은 구간을 한 차례 훑는 과정을 패스(pass)라고 한다.**

패스를 한 번 마칠 때마다 오른쪽에 있는 원소 하나의 최종 위치가 확정된다. 따라서 다음 패스에서는 비교 범위를 하나 줄일 수 있다.

---

## 정렬 과정

다음 리스트를 오름차순으로 정렬하는 상황이다.

```
[5, 1, 4, 2, 8]
```

### 첫 번째 패스

왼쪽부터 인접한 두 원소를 비교한다.

|비교 대상|동작|리스트 상태|
|---|---|---|
|5와 1|5가 더 크므로 교환한다.|`[1, 5, 4, 2, 8]`|
|5와 4|5가 더 크므로 교환한다.|`[1, 4, 5, 2, 8]`|
|5와 2|5가 더 크므로 교환한다.|`[1, 4, 2, 5, 8]`|
|5와 8|순서가 맞으므로 유지한다.|`[1, 4, 2, 5, 8]`|

첫 번째 패스가 끝나면 가장 큰 값인 `8`의 위치가 확정된다.

```
[1, 4, 2, 5 | 8]
              확정
```

이번 예제에서는 `8`이 처음부터 마지막에 있었다. 그렇더라도 첫 패스를 마친 시점에 전체 최댓값이 마지막에 있다는 사실이 보장된다.

### 두 번째 패스

위치가 확정된 `8`을 제외하고 비교한다.

|비교 대상|동작|리스트 상태|
|---|---|---|
|1과 4|순서가 맞으므로 유지한다.|`[1, 4, 2, 5, 8]`|
|4와 2|4가 더 크므로 교환한다.|`[1, 2, 4, 5, 8]`|
|4와 5|순서가 맞으므로 유지한다.|`[1, 2, 4, 5, 8]`|

두 번째 패스가 끝나면 남은 구간의 최댓값인 `5`의 위치가 확정된다.

```
[1, 2, 4 | 5, 8]
           확정
```

이 시점에는 리스트 전체가 정렬되어 있다. 다만 알고리즘이 이를 확인하려면 다음 패스에서 교환이 발생하는지 살펴봐야 한다.

### 세 번째 패스

남은 구간인 `[1, 2, 4]`를 비교한다.

|비교 대상|동작|리스트 상태|
|---|---|---|
|1과 2|순서가 맞으므로 유지한다.|`[1, 2, 4, 5, 8]`|
|2와 4|순서가 맞으므로 유지한다.|`[1, 2, 4, 5, 8]`|

이번 패스에서는 교환이 한 번도 발생하지 않는다.

**한 패스 전체에서 교환이 발생하지 않았다면 정렬이 완료된 상태이므로 즉시 종료할 수 있다.**

## 예제 코드

다음 코드는 비교 범위를 점차 줄이고, 교환이 없는 패스에서는 조기에 종료하도록 구현한 버블 정렬이다.

```
def bubble_sort(numbers: list[int]) -> None:
    """전달받은 리스트를 버블 정렬로 오름차순 정렬한다."""
    n = len(numbers)

    for pass_index in range(n - 1):
        swapped = False

        # 오른쪽에서 위치가 확정된 원소는 비교에서 제외한다.
        for j in range(n - 1 - pass_index):
            if numbers[j] > numbers[j + 1]:
                numbers[j], numbers[j + 1] = (
                    numbers[j + 1],
                    numbers[j],
                )
                swapped = True

        # 교환이 없으면 정렬이 완료된 상태이므로 종료한다.
        if not swapped:
            break


numbers = [5, 1, 4, 2, 8]

print("정렬 전:", numbers)
bubble_sort(numbers)
print("정렬 후:", numbers)
```

실행 결과는 다음과 같다.

```
정렬 전: [5, 1, 4, 2, 8]
정렬 후: [1, 2, 4, 5, 8]
```

이 함수는 전달받은 리스트 자체를 수정하며 반환값은 `None`이다. 따라서 정렬 결과를 사용하려면 함수 호출 이후의 `numbers`를 사용하면 된다.

### 바깥쪽 반복문

```
for pass_index in range(n - 1):
```

원소가 `n`개라면 최대 `n - 1`번의 패스를 수행한다.

각 패스에서 원소 하나의 위치가 확정되므로, `n - 1`개 원소의 위치가 확정되면 나머지 원소의 위치도 자동으로 결정된다.

### 안쪽 반복문

```
for j in range(n - 1 - pass_index):
```

`numbers[j]`와 `numbers[j + 1]`을 비교하므로 비교 인덱스는 마지막 원소의 바로 앞까지만 사용한다.

또한 패스가 끝날 때마다 오른쪽 원소 하나의 위치가 확정되므로 `pass_index`만큼 비교 범위를 줄인다.

원소가 5개라면 패스별 최대 비교 횟수는 다음과 같다.

```
첫 번째 패스: 4번
두 번째 패스: 3번
세 번째 패스: 2번
네 번째 패스: 1번
```

### 비교와 교환

```
if numbers[j] > numbers[j + 1]:
    numbers[j], numbers[j + 1] = (
        numbers[j + 1],
        numbers[j],
    )
```

왼쪽 값이 오른쪽 값보다 크면 두 값을 교환한다.

Python의 다중 대입을 사용하면 임시 변수를 직접 선언하지 않고 두 원소를 교환할 수 있다.

### 조기 종료

```
if not swapped:
    break
```

각 패스 시작 시 `swapped`를 `False`로 초기화하고, 실제 교환이 일어나면 `True`로 바꾼다.

패스가 끝날 때까지 `False`라면 정렬되지 않은 구간의 모든 인접 원소가 이미 오름차순이다. 오른쪽 구간도 이전 패스에서 위치가 확정되었으므로 전체 정렬을 종료할 수 있다.

## 시간 복잡도

버블 정렬의 실행 시간은 원소 비교와 교환 횟수에 영향을 받는다.

|상황|시간 복잡도|설명|
|---|---|---|
|최선|`O(n)`|이미 정렬되어 있으면 첫 패스에서 교환 없이 종료한다.|
|평균|`O(n²)`|일반적인 입력에서는 여러 패스에 걸쳐 비교와 교환을 수행한다.|
|최악|`O(n²)`|역순 입력에서는 최대 패스와 비교 횟수가 필요하다.|

### 최악의 경우 비교 횟수

원소가 `n`개일 때 최대 비교 횟수는 다음과 같다.

```
(n - 1) + (n - 2) + ... + 2 + 1
= n(n - 1) / 2
```

가장 큰 항이 `n²`에 비례하므로 시간 복잡도는 `O(n²)`이다.

예를 들어 원소가 1,000개라면 최대 비교 횟수는 다음과 같다.

```
1,000 × 999 / 2 = 499,500번
```

원소가 10,000개라면 다음과 같다.

```
10,000 × 9,999 / 2 = 49,995,000번
```

**데이터 개수가 10배가 되면 최대 비교 횟수는 약 100배로 증가한다.**

### 최선의 경우와 조기 종료의 관계

위 구현은 이미 정렬된 리스트를 한 번 순회한 뒤 종료하므로 최선의 시간 복잡도가 `O(n)`이다.

조기 종료 조건을 제거하면 정렬된 리스트에서도 모든 패스를 수행하므로 최선의 경우에도 `O(n²)`이다.

## 공간 복잡도와 안정성

### 공간 복잡도는 O(1)이다

위 구현은 입력 리스트 외에 데이터 크기에 비례하는 추가 저장 공간을 만들지 않는다.

반복문 인덱스와 교환 여부를 나타내는 변수 등 일정한 크기의 추가 공간만 사용한다. 따라서 추가 공간 복잡도는 `O(1)`이다.

이처럼 원본 자료구조 안에서 원소를 재배치하는 정렬을 **제자리 정렬(in-place sort)**이라고 한다.

### 안정 정렬이다

**안정 정렬(stable sort)은 정렬 기준값이 같은 원소들의 기존 상대적 순서를 유지하는 정렬이다.**

예를 들어 점수를 기준으로 정렬하는 데이터가 다음과 같다고 가정한다.

```
[("민수", 80), ("지수", 70), ("영희", 80)]
```

안정 정렬을 적용하면 결과는 다음과 같다.

```
[("지수", 70), ("민수", 80), ("영희", 80)]
```

같은 80점인 민수와 영희의 순서가 유지된다.

위 버블 정렬 구현은 다음 조건을 사용하므로 안정 정렬이다.

```
if numbers[j] > numbers[j + 1]:
```

값이 같을 때는 교환하지 않으므로 같은 값의 원소들이 서로를 추월하지 않는다.

반대로 비교 조건을 `>=`로 바꾸면 같은 값의 원소도 교환하므로 안정성이 깨질 수 있다.

## 장점과 한계

### 장점

- 인접한 두 원소의 비교와 교환만 사용하므로 동작을 이해하기 쉽다.
- 구현이 짧아 정렬 알고리즘의 기본 개념을 학습하기에 적합하다.
- 추가 공간 복잡도가 `O(1)`이다.
- 같은 값끼리 교환하지 않으면 안정 정렬이다.
- 조기 종료를 적용하면 이미 정렬된 입력을 `O(n)`에 처리한다.

### 한계

- 평균과 최악의 시간 복잡도가 `O(n²)`이므로 큰 데이터에서는 비효율적이다.
- 원소를 인접한 위치로만 이동시키므로 많은 교환이 발생할 수 있다.
- 거의 정렬된 데이터라도 원소 배치에 따라 많은 패스가 필요할 수 있다.

마지막 특징은 다음 예제로 이해할 수 있다.

```
[2, 3, 4, 5, 1]
```

위 구현은 왼쪽에서 오른쪽으로 비교하므로 큰 값은 한 패스에서 여러 칸 오른쪽으로 이동할 수 있다. 반면 마지막의 `1`은 한 패스에서 왼쪽으로 한 칸씩만 이동한다.

따라서 겉으로는 대부분 정렬되어 있어도 여러 패스가 필요하다.

실제 Python 프로그램에서 일반적인 정렬을 수행할 때는 다음과 같은 내장 기능을 사용하는 것이 보통 더 적합하다.

```
# 기존 리스트를 직접 정렬한다.
numbers.sort()

# 원본을 유지하면서 새 정렬 리스트를 만든다.
sorted_numbers = sorted(numbers)
```

버블 정렬에서 가장 중요한 원리는 **인접한 두 원소를 반복해서 비교하며, 각 패스마다 남은 구간의 최댓값을 오른쪽 끝에 확정한다는 점**이다.
