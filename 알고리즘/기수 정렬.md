## 기수 정렬의 개념

**기수 정렬(Radix Sort)은 값을 자릿수별로 나누어 처리하면서 전체 데이터를 정렬하는 알고리즘이다.**

예를 들어 정수를 정렬할 때 일의 자리, 십의 자리, 백의 자리처럼 각 자리의 숫자를 기준으로 반복해서 정렬한다.

앞에서 살펴본 버블 정렬, 병합 정렬, 퀵 정렬 등은 원소끼리 크기를 비교하는 **비교 기반 정렬**이다.

기수 정렬은 원소 전체의 대소 관계를 직접 비교하는 대신, **각 자릿수의 값을 이용하여 원소를 분류하는 비비교 정렬**이다.

예를 들어 다음 두 수를 처리한다고 가정한다.

```
170
 45
```

기수 정렬에서는 처음부터 `170 > 45`인지 비교하지 않는다. 각 수의 일의 자리, 십의 자리, 백의 자리를 차례대로 처리하여 최종 순서를 결정한다.

---

## LSD 방식과 MSD 방식

기수 정렬은 자릿수를 처리하는 방향에 따라 크게 두 가지로 나뉜다.

### LSD 방식

**LSD(Least Significant Digit)는 가장 낮은 자리부터 처리하는 방식이다.**

십진수 정수에서는 다음 순서로 진행한다.

```
일의 자리 → 십의 자리 → 백의 자리 → 천의 자리 → ...
```

각 자리에서 전체 데이터를 안정적으로 정렬한다.

이 설명과 Python 구현에서는 이해하기 쉬운 **LSD 기수 정렬**을 사용한다.

### MSD 방식

**MSD(Most Significant Digit)는 가장 높은 자리부터 처리하는 방식이다.**

먼저 가장 높은 자리의 값에 따라 데이터를 나눈다. 이후 같은 그룹에 속한 원소들을 다음 자리로 다시 나누어 처리한다.

고정 길이 정수뿐 아니라 문자열을 앞 글자부터 분류하는 방식에도 활용할 수 있다. 가변 길이 문자열에서는 문자열이 끝나는 경우도 별도로 처리해야 한다.

|구분|LSD 방식|MSD 방식|
|---|---|---|
|시작 위치|가장 낮은 자리부터 시작한다.|가장 높은 자리부터 시작한다.|
|진행 방법|전체 데이터에 자릿수 정렬을 반복한다.|나뉜 그룹 안에서 다음 자리를 처리한다.|
|핵심 조건|각 자릿수 정렬의 안정성이 필요하다.|그룹 분할과 다음 자리 처리가 필요하다.|

---

## LSD 기수 정렬의 핵심 원리

음수가 없는 십진수 정수를 기준으로 처리 순서는 다음과 같다.

1. 가장 큰 값의 자릿수를 확인한다.
2. 일의 자리 숫자를 기준으로 안정 정렬한다.
3. 십의 자리 숫자를 기준으로 안정 정렬한다.
4. 가장 높은 자리까지 같은 과정을 반복한다.
5. 모든 자리의 처리가 끝나면 전체 정렬이 완료된다.

각 자리의 숫자는 `0`부터 `9`까지이므로, 자릿수별로 10개의 그룹을 사용할 수 있다.

```
0번 그룹
1번 그룹
2번 그룹
...
9번 그룹
```

원소들을 해당 그룹에 넣은 뒤 `0`번부터 `9`번까지 순서대로 모은다.

**같은 그룹에 들어가는 원소들은 기존 순서를 유지해야 한다.**

또한 어떤 수에 해당 자리가 없으면 그 자리의 숫자를 `0`으로 취급한다.

```
2의 백의 자리 숫자는 0이다.
45의 백의 자리 숫자도 0이다.
170의 백의 자리 숫자는 1이다.
```

## 정렬 과정

다음 리스트를 오름차순으로 정렬하는 상황이다.

```
[170, 45, 75, 90, 802, 24, 2, 66]
```

최댓값은 `802`이며 세 자리 수이다. 따라서 일의 자리, 십의 자리, 백의 자리를 처리한다.

### 첫 번째 단계: 일의 자리를 기준으로 정렬한다

현재 순서대로 원소를 확인하여 일의 자리 숫자에 해당하는 그룹에 넣는다.

|일의 자리|해당 원소|
|---|---|
|0|`170`, `90`이다.|
|1|해당 원소가 없다.|
|2|`802`, `2`이다.|
|3|해당 원소가 없다.|
|4|`24`이다.|
|5|`45`, `75`이다.|
|6|`66`이다.|
|7~9|해당 원소가 없다.|

그룹을 작은 숫자부터 모으면 다음과 같다.

```
[170, 90, 802, 2, 24, 45, 75, 66]
```

이 단계에서는 **일의 자리 숫자만 정렬된 상태**이다. 전체 수의 크기순으로 정렬된 상태는 아니다.

같은 일의 자리인 `802`와 `2`는 기존 순서를 유지한다. `45`와 `75`도 기존 순서를 유지한다.

### 두 번째 단계: 십의 자리를 기준으로 정렬한다

직전 단계의 결과를 현재 순서대로 처리한다.

```
[170, 90, 802, 2, 24, 45, 75, 66]
```

|십의 자리|해당 원소|
|---|---|
|0|`802`, `2`이다.|
|1|해당 원소가 없다.|
|2|`24`이다.|
|3|해당 원소가 없다.|
|4|`45`이다.|
|5|해당 원소가 없다.|
|6|`66`이다.|
|7|`170`, `75`이다.|
|8|해당 원소가 없다.|
|9|`90`이다.|

그룹을 모으면 다음과 같다.

```
[802, 2, 24, 45, 66, 170, 75, 90]
```

이제 **마지막 두 자리의 값이 오름차순인 상태**이다.

```
02, 02, 24, 45, 66, 70, 75, 90
```

십의 자리가 같은 원소들은 이전 단계에서 만든 일의 자리 순서를 유지한다.

### 세 번째 단계: 백의 자리를 기준으로 정렬한다

직전 결과를 백의 자리 숫자로 분류한다.

```
[802, 2, 24, 45, 66, 170, 75, 90]
```

|백의 자리|해당 원소|
|---|---|
|0|`2`, `24`, `45`, `66`, `75`, `90`이다.|
|1|`170`이다.|
|2~7|해당 원소가 없다.|
|8|`802`이다.|
|9|해당 원소가 없다.|

그룹을 모으면 최종 정렬 결과가 된다.

```
[2, 24, 45, 66, 75, 90, 170, 802]
```

전체 변화는 다음과 같다.

```
초기 상태
[170, 45, 75, 90, 802, 24, 2, 66]

일의 자리 처리 후
[170, 90, 802, 2, 24, 45, 75, 66]

십의 자리 처리 후
[802, 2, 24, 45, 66, 170, 75, 90]

백의 자리 처리 후
[2, 24, 45, 66, 75, 90, 170, 802]
```

---

## 안정 정렬이 반드시 필요한 이유

**안정 정렬은 정렬 기준값이 같은 원소들의 기존 상대적 순서를 유지하는 정렬이다.**

LSD 기수 정렬에서는 낮은 자리에서 만든 순서를 높은 자리 처리 중에도 보존해야 한다.

다음 리스트를 정렬하는 상황이다.

```
[12, 11]
```

일의 자리를 기준으로 정렬하면 다음과 같다.

```
[11, 12]
```

다음으로 십의 자리를 처리하면 두 값 모두 십의 자리 숫자가 `1`이다.

이때 기존 순서를 유지하면 올바른 결과가 나온다.

```
[11, 12]
```

반대로 같은 십의 자리라는 이유로 순서가 뒤집히면 다음과 같이 잘못된 결과가 된다.

```
[12, 11]
```

따라서 **현재 자리의 숫자가 같을 때는 이전 단계에서 정리한 낮은 자리의 순서를 유지해야 한다.**

이 원리에 따라 각 단계가 끝나면 다음 상태를 보장한다.

- 일의 자리 처리 후에는 마지막 한 자리가 정렬된다.
- 십의 자리 처리 후에는 마지막 두 자리가 정렬된다.
- 백의 자리 처리 후에는 마지막 세 자리가 정렬된다.

가장 높은 자리까지 처리하면 전체 값이 정렬된다.

## 예시 코드

다음 코드는 **0 이상의 정수**를 대상으로 한다.

각 자릿수를 정렬하는 데에는 안정적인 **계수 정렬(Counting Sort)**을 사용한다. 계수 정렬은 각 값의 등장 횟수를 세고, 그 정보를 이용하여 원소를 배치하는 정렬이다.

```
def counting_sort_by_digit(
    numbers: list[int],
    exp: int,
) -> list[int]:
    """exp가 가리키는 자릿수를 기준으로 안정 정렬한다."""
    counts = [0] * 10
    output = [0] * len(numbers)

    # 각 자릿수 숫자의 등장 횟수를 센다.
    for value in numbers:
        digit = (value // exp) % 10
        counts[digit] += 1

    # 각 숫자 이하의 원소 개수를 누적한다.
    for digit in range(1, 10):
        counts[digit] += counts[digit - 1]

    # 같은 자릿수의 기존 순서를 유지하도록 뒤에서부터 배치한다.
    for i in range(len(numbers) - 1, -1, -1):
        value = numbers[i]
        digit = (value // exp) % 10

        counts[digit] -= 1
        output[counts[digit]] = value

    return output


def radix_sort(numbers: list[int]) -> list[int]:
    """0 이상의 정수를 기수 정렬한 새 리스트를 반환한다."""
    if not numbers:
        return []

    if any(value < 0 for value in numbers):
        raise ValueError("0 이상의 정수만 정렬할 수 있다.")

    result = numbers.copy()
    max_value = max(result)
    exp = 1

    # 일의 자리부터 최댓값의 가장 높은 자리까지 처리한다.
    while max_value // exp > 0:
        result = counting_sort_by_digit(result, exp)
        exp *= 10

    return result


numbers = [170, 45, 75, 90, 802, 24, 2, 66]
sorted_numbers = radix_sort(numbers)

print("원본:", numbers)
print("정렬 결과:", sorted_numbers)
```

실행 결과는 다음과 같다.

```
원본: [170, 45, 75, 90, 802, 24, 2, 66]
정렬 결과: [2, 24, 45, 66, 75, 90, 170, 802]
```

**이 구현은 원본 리스트를 변경하지 않고, 정렬된 새 리스트를 반환한다.**

모든 원소가 `0`이면 자릿수 반복문을 실행하지 않지만, 복사한 리스트 자체가 이미 정렬되어 있으므로 올바른 결과를 반환한다.

## 코드의 세부 동작

### exp는 처리할 자릿수를 나타낸다

```
exp = 1
```

`exp`의 값에 따라 다음 자리를 처리한다.

|exp|처리하는 자리|
|---|---|
|1|일의 자리이다.|
|10|십의 자리이다.|
|100|백의 자리이다.|
|1000|천의 자리이다.|

한 자리의 처리가 끝나면 다음과 같이 10배 증가시킨다.

```
exp *= 10
```

### 특정 자리의 숫자를 추출한다

```
digit = (value // exp) % 10
```

먼저 `// exp`로 처리할 자리 아래의 숫자를 제거한다. 이후 `% 10`으로 남은 값의 마지막 숫자를 구한다.

`802`의 자릿수를 추출하면 다음과 같다.

```
일의 자리: (802 // 1) % 10 = 2

십의 자리: (802 // 10) % 10 = 0

백의 자리: (802 // 100) % 10 = 8
```

### 등장 횟수를 누적합으로 바꾼다

```
for digit in range(1, 10):
    counts[digit] += counts[digit - 1]
```

등장 횟수만으로는 결과 리스트의 어느 위치에 원소를 배치할지 바로 알기 어렵다.

누적합을 계산하면 `counts[digit]`는 해당 숫자 이하의 원소 개수가 된다.

예를 들어 누적합 계산 후 다음 상태라면 다음 의미이다.

```
counts[2] = 4
```

현재 자리의 숫자가 `2` 이하인 원소가 총 4개라는 의미이다. 따라서 숫자 `2`인 원소가 들어갈 구간은 늦어도 인덱스 `3`에서 끝난다.

배치 직전에 개수를 하나 줄이면 실제로 사용할 인덱스를 얻는다.

```
counts[digit] -= 1
output[counts[digit]] = value
```

### 뒤에서부터 배치하는 이유

```
for i in range(len(numbers) - 1, -1, -1):
```

이 구현은 각 그룹의 뒤쪽 위치부터 채운다.

같은 자릿수의 원소 중 뒤에 있던 원소를 먼저 뒤쪽에 배치하고, 앞에 있던 원소를 그 앞에 배치하면 기존 순서가 유지된다.

**누적합으로 그룹의 끝 위치를 계산하고 뒤에서부터 채우는 두 동작이 함께 안정성을 보장한다.**

### 가장 높은 자리를 처리하면 종료한다

```
while max_value // exp > 0:
```

최댓값이 `802`이면 `exp`가 `1`, `10`, `100`일 때 반복문을 실행한다.

`exp`가 `1000`이 되면 다음 조건이 성립한다.

```
802 // 1000 = 0
```

더 처리할 자리가 없으므로 종료한다.

## 시간 복잡도와 공간 복잡도

### 시간 복잡도는 O(d(n + b))이다

다음 기호를 사용한다.

- `n`은 원소 개수이다.
- `d`는 처리할 최대 자릿수이다.
- `b`는 각 자리에서 가능한 숫자의 개수인 기수이다.

십진수에서는 `b = 10`이다.

한 자리의 정렬에서는 다음 작업을 수행한다.

1. 전체 원소의 자릿수를 확인하여 횟수를 센다.
2. `b`개의 숫자에 대해 누적합을 계산한다.
3. 전체 원소를 결과 리스트에 배치한다.

따라서 한 자리의 처리 비용은 `O(n + b)`이다.

이를 `d`자리 동안 반복하므로 전체 시간 복잡도는 다음과 같다.

```
O(d(n + b))
```

십진수처럼 `b`를 고정하면 다음과 같이 표현한다.

```
O(dn)
```

### 항상 O(n)인 것은 아니다

자릿수 `d`가 일정하게 제한되어 있다면 입력 개수에 대해 선형 시간으로 볼 수 있다.

예를 들어 값이 항상 `0`부터 `999`까지라면 최대 세 자리만 처리한다.

반면 입력값이 커질수록 자릿수도 늘어난다면 `d`를 상수로 취급할 수 없다.

**기수 정렬의 성능은 원소 개수뿐 아니라 값의 자릿수에도 영향을 받는다.**

이 분석은 자릿수 추출과 기본 연산을 상수 시간으로 보는 기준이다. Python에서 매우 큰 정수를 다룰 때는 정수 연산 자체의 비용도 고려해야 한다.

### 공간 복잡도는 O(n + b)이다

결과를 담을 원소 `n`개짜리 리스트와, 등장 횟수를 담을 `b`개짜리 리스트가 필요하다.

따라서 추가 공간 복잡도는 다음과 같다.

```
O(n + b)
```

십진수처럼 `b`가 고정되어 있으면 `O(n)`이다.

|항목|복잡도|
|---|---|
|한 자리의 처리 시간|`O(n + b)`이다.|
|전체 처리 시간|`O(d(n + b))`이다.|
|추가 공간|`O(n + b)`이다.|
|십진수에서의 전체 처리 시간|`O(dn)`이다.|
|십진수에서의 추가 공간|`O(n)`이다.|

위 구현은 이미 정렬된 입력도 같은 자릿수들을 처리하므로, 입력 순서에 따른 조기 종료 효과는 없다.

## 음수를 처리하는 방법

앞의 기본 구현은 음수를 허용하지 않는다.

음수가 포함된 정수를 처리하는 한 가지 방법은 **모든 값에 같은 수를 더하여 0 이상의 값으로 변환하는 방식**이다.

예를 들어 다음 입력이 주어진 상황이다.

```
[-12, 5, -3, 0]
```

최솟값이 `-12`이므로 모든 값에 `12`를 더한다.

```
[0, 17, 9, 12]
```

이 리스트를 기수 정렬한다.

```
[0, 9, 12, 17]
```

마지막으로 모든 값에서 `12`를 빼면 원래 값의 정렬 결과를 얻는다.

```
[-12, -3, 0, 5]
```

모든 값에 같은 수를 더해도 대소 관계가 유지되므로 사용할 수 있는 방법이다.

앞에서 작성한 `radix_sort()`를 이용하면 다음과 같이 구현한다.

```
def radix_sort_signed(numbers: list[int]) -> list[int]:
    """음수를 포함한 정수를 기수 정렬한 새 리스트를 반환한다."""
    if not numbers:
        return []

    min_value = min(numbers)
    offset = -min_value if min_value < 0 else 0

    # 모든 값을 0 이상으로 변환한다.
    shifted = [value + offset for value in numbers]

    # 앞에서 구현한 기수 정렬을 적용한다.
    sorted_shifted = radix_sort(shifted)

    # 더했던 값을 빼서 원래 값으로 복원한다.
    return [value - offset for value in sorted_shifted]


numbers = [-12, 5, -3, 0]

print(radix_sort_signed(numbers))
```

실행 결과는 다음과 같다.

```
[-12, -3, 0, 5]
```

이 방식에서는 변환된 최댓값의 자릿수를 기준으로 정렬 비용이 결정된다.

## 비교 기반 정렬보다 빠를 수 있는 이유

비교 기반 정렬은 일반적인 입력의 정렬 순서를 원소 간 비교 결과로 알아내야 한다.

이 모델에서는 최악의 경우 `Ω(n log n)`번의 비교가 필요하다. 여기서 `Ω`는 필요한 작업량의 하한을 나타낸다.

기수 정렬은 각 원소의 자릿수라는 추가 구조를 사용한다.

따라서 **비교 기반 정렬의 하한이 기수 정렬에 그대로 적용되지는 않는다.**

다만 기수 정렬에는 다음 조건이 필요하다.

- 값을 자릿수나 일정한 단위로 분해할 수 있어야 한다.
- 각 자리의 값으로 원소를 분류할 수 있어야 한다.
- 자릿수가 지나치게 많지 않아야 효율적이다.
- LSD 방식에서는 각 자리의 정렬이 안정적이어야 한다.

기수 정렬이 모든 데이터에서 비교 기반 정렬보다 빠르다는 의미는 아니다. 데이터 표현과 자릿수, 메모리 사용량에 따라 유불리가 달라진다.

## 계수 정렬·버킷 정렬과의 관계

### 계수 정렬과의 관계

계수 정렬은 값의 등장 횟수를 세어 정렬한다.

예를 들어 값 전체를 계수 정렬하면, 다루는 값의 범위에 따라 큰 개수 배열이 필요할 수 있다.

기수 정렬에서는 각 자리의 숫자만 계수 정렬한다. 십진수라면 한 번에 다루는 값은 `0`부터 `9`까지이다.

**앞의 구현은 작은 범위의 안정적인 계수 정렬을 자릿수마다 반복하는 기수 정렬이다.**

### 버킷을 사용하는 구현

각 자릿수에 대해 10개의 리스트를 만들고 원소를 넣은 뒤 순서대로 모으는 구현도 가능하다.

원소를 앞에서부터 각 버킷에 추가하고, 버킷 내부 순서를 유지하여 모으면 안정성을 확보할 수 있다.

다만 기수 정렬과 일반적인 버킷 정렬은 동일한 알고리즘은 아니다. 기수 정렬은 여러 자리를 차례대로 처리하여 전체 순서를 만드는 것이 핵심이다.

---

## 장점과 한계

### 장점

- 자릿수가 제한된 정수에서는 원소 개수에 대해 선형 시간에 가까운 처리가 가능하다.
- 원소 전체의 대소 비교를 반복하지 않는다.
- 안정적인 자릿수 정렬을 사용하면 전체 정렬도 안정적이다.
- 정수뿐 아니라 일정한 규칙으로 분해할 수 있는 키에도 적용할 수 있다.

### 한계

- 원소 개수 외에 자릿수와 기수도 실행 시간에 영향을 준다.
- 앞의 구현은 `O(n)`의 추가 공간이 필요하다.
- 음수, 실수, 문자열 등은 표현 방식에 맞는 추가 설계가 필요하다.
- 자릿수가 매우 많으면 반복 횟수가 증가한다.
- 임의의 객체에 비교 함수만 제공하여 바로 적용하는 일반적인 비교 정렬과는 사용 조건이 다르다.
